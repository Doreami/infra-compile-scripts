## 三、建表 & 数据导入 & 建索引 SQL

### 数据导入

```bash
# SIFT 二进制 → Parquet（10 文件，每文件 100K 行）
python3 convert_sift.py \
  --input ~/端到端性能测试/ \
  --warehouse file://$HOME/warehouse \
  --namespace sift_ns \
  --table sift1m
```

### 建表

```sql
-- 创建命名空间
SELECT iceberg_catalog.create_namespace('sift_ns', '{}'::jsonb);

-- Iceberg 表（通过 pyiceberg SDK 创建并 append Parquet 文件）
-- Schema: id (long) + vec (list<float>)

-- openGauss 外部表
CREATE FOREIGN TABLE sift_ns.sift1m (id bigint, vec vector(128))
SERVER iceberg_catalog_server OPTIONS (namespace 'sift_ns', table_name 'sift1m');

-- 注册 catalog 元数据
INSERT INTO iceberg_catalog.tables_internal(
  relid, namespace, table_name, table_uuid, metadata_location,
  previous_metadata_location, table_location, last_column_id,
  current_schema_id, current_snapshot_id, default_spec_id)
VALUES ('sift_ns.sift1m'::regclass, 'sift_ns', 'sift1m', '<uuid>'::uuid,
  'file:///home/xl/warehouse/sift_ns/sift1m/metadata/<uuid>.metadata.json',
  NULL, 'file:///home/xl/warehouse/sift_ns/sift1m', 2, 0, <snapshot_id>, 0);

INSERT INTO iceberg_catalog.table_schemas(table_uuid, schema_id, field_position, field_id, field_name, field_required, field_type)
VALUES
  ('<uuid>'::uuid, 0, 0, 1, 'id', 'true', 'bigint'),
  ('<uuid>'::uuid, 0, 1, 2, 'vec', 'false', 'vector(128)');
```

### Btree 索引


- 查询向量: 取 id=500000 的 128 维 float 向量常量（子查询会阻止索引匹配）

### 测试项 1: Btree 点查

**说明**: 主键等值查询，验证标量索引性能。

**SQL**:

```sql
SELECT * FROM sift_ns.sift1m WHERE id = 500000;
```

| | Run1 | Run2 | Run3 | 平均 |
|---|------|------|------|------|
| btree 索引 | 174 | 172 | 170 | **171 ms** |

> btree 索引扫描：Foreign Scan 1 行，bridge scalar index scan。EXPLAIN 显示 `Index Name: idx_btree_id`。

**说明**: IVF (num_clusters=1024) 加速，`FetchK=50`（默认探头数）。

## 六、性能总览

| 测试项 | 全扫 (ms) | 索引扫 (ms) | 加速比 | 7/15 加速比 | 变化 |
|--------|-----------|-------------|--------|-------------|------|
| Btree 点查 | 76 (7/15) | **171** | 0.44x | 0.43x | 持平 |
| Top-10 | 2,416 | **1,044** | **2.3x** | 2.9x | -0.6x |

### IVF K=10 两次测试对比

| 维度 | 7/15 (无帧指针) | 7/16 (帧指针版) |
|------|-----------------|-----------------|
| 全扫 | 2,436 ms | 2,416 ms |
| IVF (warm) | 839 ms | 1,044 ms |
| 加速比 | 2.9x | 2.3x |
| 编译 | Release | Release + `-fno-omit-frame-pointer` |
| bridge commit | (旧版) | `23aa21e` |
| gaussdb commit | (旧版) | `003ec9240` |

IVF 慢 ~200ms 的可能原因:
1. 本次重编译的 bridge/gaussdb 版本不同
2. 帧指针编译有 0-2% 的理论性能影响
3. k-means 聚类重建后分布略有不同（随机初始化）
4. 服务器负载波动

---

## 七、总结

1. **全扫耗时稳定**: 7/15 = 2,436ms, 7/16 = 2,416ms，差异 <1%，结果可信
2. **IVF 加速有效但不达理论值**: warm 1,044ms vs 全扫 2,416ms，加速 2.3x。瓶颈不在索引搜索（CPU <1%），而在 Parquet 页级解码（~976 行/聚类）和固定开销（索引文件 ~390ms）
3. **Btree 点查**: 171ms，热点在 gaussdb 共享内存初始化（>40% CPU），非数据读取
4. **帧指针编译生效**: 火焰图调用栈从 `ExecInitVectorSearch` 完整追溯至 `ListArrayReader::consume_batch`，无错位
5. **冷启动开销**: 首次 IVF ~3.3s（索引文件 502MB 加载 + bridge 初始化），预热后稳定

### 附带测试：数据导入修正

`convert_sift.py` 原本写入 `sift_ns.db/` 而 Iceberg catalog 使用 `sift_ns/`，路径不匹配导致 `count(*)` 返回 0。修复方式：
1. 去掉脚本中 `{namespace}.db` 的 `.db` 后缀
2. 使用 pyiceberg SDK 的 `table.append()` 注册 Parquet 文件生成 snapshot
3. 通过 `INSERT INTO iceberg_catalog.tables_internal` 在 openGauss 注册元数据
