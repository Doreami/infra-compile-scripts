## 三、建表 & 建索引 SQL

### 建表

```sql
CREATE SCHEMA IF NOT EXISTS sift_ns;

CREATE FOREIGN TABLE sift_ns.sift1m (id bigint, vec vector(128))
SERVER iceberg_catalog_server OPTIONS (namespace 'sift_ns', table_name 'sift1m');
```

### Btree 索引

```sql
SELECT iceberg_catalog.create_index(
    'sift_ns', 'sift1m', 'idx_btree_id',
    '["id"]'::jsonb,
    'btree', 'btree',
    '{"key_column":"id"}'::jsonb
);
```

### IVF 向量索引

```sql
SELECT iceberg_catalog.create_index(
    'sift_ns', 'sift1m', 'idx_ivf_vec',
    '["vec"]'::jsonb,
    'ivf_flat', 'ivf',
    '{"num_clusters":1024, "sample_rate":100000}'::jsonb
);
```

索引文件: `indices/default/builtin.ivf_flat_v2_idx_ivf_vec_*.puffin` (502 MB)

### 测试项 3: IVF probes 参数对比 (K=10)

**SQL**:

```sql
SET enable_vectorsearch = on; SET try_vector_engine_strategy = force;
SET ivfflat_probes = <N>;
SELECT id FROM sift_ns.sift1m
ORDER BY vec <-> '[...]'::vector LIMIT 10;
```

| probes | 耗时 | vs probes=1 |
|--------|------|-------------|
| 1 | **983 ms** | — |
| 8 | 984 ms | +0.1% |
| 32 | 991 ms | +0.8% |

> probes 1→32 耗时几乎无变化（<1%）。probes 增加意味着扫描更多聚类，但 Parquet 页级解码仍是主导开销，候选集合并成本可忽略。火焰图分析确认索引搜索 CPU <1%。

## 六、性能总览

| 测试项 | 全扫 (ms) | IVF (ms) | 加速比 |
|--------|-----------|----------|--------|
| Btree 点查 | 76 (7/15) | **171** | 0.44x |
| Top-10 | 2,416 | **1,044** | **2.3x** |
| Top-50 | 2,426 | **1,641** | **1.48x** |
| Top-500 | 2,428 | **1,657** | **1.47x** |

### 与 7/15 对比

| K | 全扫 7/15 | 全扫 7/16 | IVF 7/15 | IVF 7/16 | 加速比 7/15 | 加速比 7/16 |
|---|-----------|-----------|----------|----------|-------------|-------------|
| 10 | 2,436 ms | 2,416 ms | 839 ms | 1,044 ms | 2.9x | 2.3x |

---

## 七、总结

1. **全扫耗时稳定**: 7/15 与 7/16 全扫 K=10 差异 <1%，结果可信
2. **IVF 加速有效但弱于 7/15**: 2.3x vs 2.9x，慢 ~200ms。帧指针编译有 0-2% 影响，bridge 版本也有差异
3. **IVF 耗时封顶 ~1,650ms**: K=10→500，全扫稳定 ~2,420ms，IVF 从 1,044ms 升至 ~1,650ms 后封顶。K 越大 IVF 优势越明显
4. **probes 对耗时无影响**: 1→32 耗时变化 <1%，索引搜索开销可忽略
5. **Btree 点查**: 171ms，瓶颈在 gaussdb 共享内存初始化（火焰图 >40% CPU），非数据读取
6. **帧指针编译生效**: 火焰图调用栈完整，`iceberg_index_rs_search_vector_by_metadata` 清晰可见
