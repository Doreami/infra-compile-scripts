## 三、关键发现

### 1. 加速比仅 1.03×（几乎无效）

GIST IVF 加速比远低于 SIFT（1.03× vs 2.3×）。根因：

- **内核开销主导**：GIST 内核占比 25.8%（全扫）远超 SIFT 的 10%。960 维 × 1M 行 = 3.84GB 向量数据，内存压力是 SIFT（512MB）的 7.5 倍，缺页频率大幅上升。
- **IVF 减少的扫描行被内核开销抵消**：IVF 只扫描 ~976 行（1 个聚类），但 Parquet 页级读取仍需解码完整数据页。
- **全扫和 IVF 热点相同**：两者 Top 热点都是内核 `[unknown]`，说明瓶颈已从 Parquet 解码转移到内存/IO。

### 2. 内核开销随维度线性增长

```
SIFT 128维 → 内核 ~10% 
GIST 960维 → 内核 ~26%（增长 2.6×，接近 960/128 = 7.5× 的子线性）
```

内核开销占比上升说明：**维度越大，内存带宽越成为瓶颈**，Parquet 解码占比相对下降。

### 3. 验证了优化分析的正确方向

| 优化项 | SIFT 收益 | GIST 收益 | 说明 |
|--------|:--------:|:--------:|------|
| P1 列裁剪 | -30% 解码 | **-30% 解码** | 跳过 vec 列减少 I/O，对 GIST 更关键 |
| P0 fixed(512) | -25% 解码 | **-25% 解码** | 消除 Rep/Def Level + ListArray |
| P3 同步 API | -10% tokio | **-5%** | 内核占比更高，tokio 相对占比下降 |

### 4. 为什么 SIFT 有加速比而 GIST 几乎没有

```
SIFT: Parquet解码(35%) + 内核(10%) + tokio(10%) = 55% 固定开销
      → IVF 减少扫描行 → 解码量 1/1024 → 加速比 2.3×

GIST: Parquet解码(15%) + 内核(26%) + tokio(5%) = 46% 固定开销  
      → 内核占比更高 → IVF 减少扫描行效果被稀释 → 加速比 1.03×
```

核心公式：**加速比 ≈ 1 / (固定开销比例 + 扫描减少比例 × 可变开销比例)**

当固定开销（特别是内核缺页）占比高时，减少扫描行的收益被稀释。

---

## 四、结论

1. **GIST1M (960维) 验证了分析方向**：瓶颈在数据管道（Parquet解码+内核），不在索引搜索
2. **P0/P1 优化对 GIST 收益更大**：列裁剪可同时减少 I/O 和解码，直接降低内核缺页
3. **索引加速比随维度递减**：需要优化 Parquet 解码管道才能在高维场景获得加速比
4. **后续**：fixed(512) 类型 + 列裁剪 两项落地后重测 GIST，预期 IVF 加速比回升到 ~1.5×
