# 稀疏回表：iceberg-rust 接入 RowSelection 设计方案

## 1. 问题

IVF 索引返回 `file_path + row_position`，回表时 `scan_single_file()` 把整个 Parquet 文件全量解码后再筛选目标行。GIST 每文件 192MB 只取 2-3 行，浪费严重。

parquet-rs 底层已有 `RowSelection` 能力（精确指定读哪些行，跳过部分不解码不物化），但 iceberg-rust 未暴露"给定 row_positions 直接取行"的接口——当前 `RowSelection` 只能从 predicate 或 deletion vector 派生。

## 2. 当前架构

```
IVF 回表路径（reader.rs scan_single_file）:
  ┌─────────────────────────────────────┐
  │ scan_single_file(file_path)         │
  │   → select(全列)                    │
  │   → plan_files() → filter file_path │
  │   → ArrowReaderBuilder.read(tasks)  │  ← 无 predicate、无 row_selection
  │   → 全文件解码成 RecordBatch        │
  │   → read_single_file_rows_addressed │
  │      逐行匹配 row_position          │
  │      99% 的行被丢弃                  │
  └─────────────────────────────────────┘

标准路径（pipeline.rs process）:
  ┌──────────────────────────────────┐
  │ FileScanTask                     │
  │   → 打开 Parquet                 │
  │   → 投影 (projection_mask)       │
  │   → RowGroup 过滤 (predicate)    │
  │   → RowSelection (predicate +    │
  │       positional delete)         │
  │   → stream batches               │
  └──────────────────────────────────┘
```

两条路径用了同一个 `ArrowReader::read()` 入口，但回表路径传的 `FileScanTask` 里没有 predicate、没有 delete、全部列投影，等于以最原始的方式跑完整条管道。

## 3. 方案

### 3.1 总体思路

在 `FileScanTask` 加 `row_offsets` 字段，在 pipeline 里把 `row_offsets` 转成 `RowSelection` 和已有的 predicate/delete 派生 `RowSelection` 做交集。调用方（IVF 回表）只需在构建 `FileScanTask` 时传入行号即可。

### 3.2 改动清单

#### A. `FileScanTask` 新增字段

文件：`crates/iceberg/src/scan/task.rs`

```rust
pub struct FileScanTask {
    // ... existing fields ...

    /// Optional sparse row offsets to read from the file.
    /// When set, only these rows are decoded from the Parquet file.
    /// Row offsets are 0-based within the file (not within a row group).
    pub row_offsets: Option<Vec<u64>>,
}
```

#### B. Pipeline 新增转换逻辑

文件：`crates/iceberg/src/arrow/reader/pipeline.rs`

在 `FileScanTaskReader::process()` 中，现有 row_selection 合并完成后（约 L418），插入：

```rust
// Merge sparse row selection from row_offsets (e.g., IVF index back-to-table)
if let Some(row_offsets) = &task.row_offsets {
    let offset_selection = ArrowReader::build_row_selection_from_row_offsets(
        record_batch_stream_builder.metadata(),
        &selected_row_group_indices,
        row_offsets,
    )?;
    row_selection = match (row_selection, offset_selection) {
        (None, offset) => offset,
        (Some(existing), Some(offset)) => Some(existing.intersection(&offset)),
        (existing, None) => existing,
    };
}
```

#### C. `build_row_selection_from_offsets` 辅助函数

文件：`crates/iceberg/src/arrow/reader/row_filter.rs`

```rust
/// Build a RowSelection from explicit row offsets (0-based within the file).
pub(super) fn build_row_selection_from_row_offsets(
    parquet_metadata: &Arc<ParquetMetaData>,
    selected_row_group_indices: &Option<Vec<usize>>,
    row_offsets: &[u64],
) -> Result<Option<RowSelection>>
```

核心逻辑：sort + dedup offsets → 遍历 row groups → 对含目标行的 rg 构建 skip/select 序列 → `RowSelection::from(selectors)`。其中用 `partition_point` 做二分查找定位每个 rg 内的偏移范围。

#### D. IVF 回表侧适配

文件：`iceberg-index/crates/iceberg-index-iceberg/src/reader.rs`

当前 `scan_single_file()` 内部自己拼了 scan → plan_files → ArrowReaderBuilder::read()。改动：

```rust
// scan_single_file 新增 row_positions 参数
async fn scan_single_file(
    &self, file_path: &str, row_positions: Option<&[u64]>,
) -> Result<IndexBatchStream> {
    // ... build scan + plan_files + filter to target_tasks ...

    // 将 IVF 回表行号写入 FileScanTask
    if let Some(positions) = row_positions {
        for task in &mut target_tasks {
            task.row_offsets = Some(positions.to_vec());
        }
    }

    // ArrowReader::read() 内部自动应用 RowSelection
    let batches = reader_builder.build().read(filtered_tasks).stream();
}
```

调用方（`read_single_file_rows` / `read_single_file_rows_addressed`）已有 `row_positions`，直接传入即可。

**⚠️ `read_single_file_rows_addressed` 的行位置匹配逻辑也须适配**（实施时踩坑）：原逻辑假定全量解码（batch 中的行从 0 开始连续编号），用 sequential counter（0,1,2...）跟踪 global position。设置 `row_offsets` 后 reader 只返回指定的行，counter 不再能正确反映真实 position。修复方式：将传入的 `row_positions` sort + dedup 后作为 sorted list，用 returned index 直接索引取真实 position，替代 counter 计算。

### 3.3 与现有功能的交互

| 功能 | 交互方式 |
|------|------|
| row_group_filtering | 无交互：RowSelection 天然覆盖 row group 级跳过（不命中候选的 row group → skip-all selector）。稀疏 take 做完后 row group 过滤基本多余 |
| predicate RowSelection | 交集：已有的 predicate `row_selection` 和 offset `row_selection` 做 `intersection()` |
| positional deletes | 交集：delete `row_selection` 也参与 `intersection()`，自动排除已删除行 |
| 列投影 | 独立：`projection_mask` 照常工作，选中列才解码 |

### 3.4 兼容性

- `row_offsets` 默认为 `None`，不传时行为完全不变
- 传给 parquet 的 `RowSelection` 对调用方透明，不影响 batch 格式
- 如果 `row_offsets` 指定的行所在的 row group 被 `selected_row_group_indices` 排除，该行被静默跳过（与现有行为一致）

## 4. 预期收益

RowSelection 是行级过滤，但通过 page index 天然附带 page 级跳过——不包含候选行的 row group 在 RowSelection 中表现为 skip-all selector，和 row group 过滤效果等价。因此**稀疏 take 做完后，row group 过滤基本多余**，边际价值仅限于省掉构建 skip-all selector 的 O(1) 开销。

实测数据（gist1m_none, 1 row group/文件）已验证：即使完全没有 row group 裁剪空间，RowSelection 仍然在 page/行级生效，-12%。

## 5. 风险

1. **`RowSelection` 与 `_pos` / `_row_id` 元数据列的交互**：当前 pipeline 在 stream 后手动追加 `_pos`（基于 `first_row_id` + 计数器）。使用 `RowSelection` 后 batch 中行变得稀疏，需要验证计数器逻辑是否正确。
2. **page index 依赖**：`RowSelection` 利用 OffsetIndex 做页级跳过。如果 Parquet 文件没有 page index（旧文件），退化到读取全部页、decoder 内 skip——开销略高但不影响正确性。
3. **小候选集**：K=10 时仅 50 个候选，建 `RowSelection` 的开销可忽略。但极端 case（K=10000，fetch_k=10000）可能产生大量 selector，需要验证性能。
