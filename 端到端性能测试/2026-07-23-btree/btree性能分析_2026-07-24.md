# SIFT1M Btree 索引性能分析

> 2026-07-24, openEuler 24.03 / 96核 / 723GB
> SIFT1M (128维), fixed(512), uncompressed, btree on `id`

## 测试目的

回答：btree 索引点查 vs 全表扫描，什么场景下 btree 有优势？

## 测试矩阵

### SIFT1M (128维, 140MB, 20文件×7MB)

| 数据排布 | 索引 | 策略 | 读文件数 | 耗时 |
|------|:--:|------|:--:|:--:|
| 顺序 | 无 | min/max 裁剪 | **1** | **95ms** |
| 顺序 | btree | 索引定位 | 1 | 112ms |
| 随机 | 无 | 全扫 | 20 | 87ms |
| 随机 | btree | 索引定位 | 1 | 109ms |

> SIFT 文件小（140MB 总量），全在 page cache，全扫也很快。btree 无优势。

### GIST1M (960维, 3.8GB, 20文件×192MB)

| 数据排布 | 索引 | 策略 | 读文件数 | 耗时 |
|------|:--:|------|:--:|:--:|
| 顺序 | 无 | min/max 裁剪 | **1** | **283ms** |
| 顺序 | btree | 索引定位 | 1 | 305ms |
| **随机** | **无** | **全扫** | **20** | **272ms** |
| **随机** | **btree** | **索引定位** | **1** | **179ms ✓** |

> GIST 单文件 192MB，20 文件共 3.8GB，全扫无法全部高效命中 page cache。btree 快 1.5x。

### 验证数据

**SIFT 顺序**（strace）：
```
FullScan: 00000-0-350fbb5b... ×3  → 1 文件
btree:    00000-0-350fbb5b... ×3  → 1 文件（min/max 裁剪）
```

**GIST 随机**（strace）：
```
btree:    3 opens   → 1 文件（索引定位）
seqscan:  41 opens  → 20 文件全部打开
```

## 分析

### 为什么随机 seqscan 反而更快？

1. **数据在小 page cache**：刚导入，20 文件 × 7MB = 140MB 全在内存，读取几乎零 I/O
2. **SDK filter 在 reader 层执行**：`Filter Mode: exact`，在 parquet 解码时直接跳过不匹配行，不产生额外 gaussdb 层开销
3. **btree 多出索引文件解析 + B-tree 遍历**：~17ms 固定开销

### 什么时候 btree 会有优势？

| 场景 | btree 优势 | 原因 |
|------|:--:|------|
| 冷 cache（数据不在内存） | **大** | 读 1 文件 vs 读 20 文件，I/O 差 20 倍 |
| 大文件（GIST 192MB×20） | **大** | 全扫 3.8GB vs btree 只读 1 文件 |
| 高频重复查询同一行 | **中** | 索引缓存命中，跳过文件打开 |
| 顺序排布 + page cache | **无** | min/max 已裁剪到 1 文件 |
| 随机排布 + page cache | **无** | 140MB 全在内存，全扫也很快 |

### 反向验证：IN 查询（模拟跨文件随机访问）

```
WHERE id IN (1, 100000, 500000, 750000, 999999)  -- 5 个不同文件
btree: 1,039ms  (5 次索引查找 + 5 次文件读)
```

这比单次点查 112ms × 5 = 560ms 慢，因为每次 btree 查找都需要重新打开文件。

## 结论

| 场景 | SIFT (140MB) | GIST (3.8GB) |
|------|:--:|:--:|
| 顺序排布 | seqscan 胜 (min/max) | seqscan 胜 (min/max) |
| 随机排布 | 持平 (page cache) | **btree 胜 (1.5x)** |
| 冷 cache | btree 胜 | **btree 大胜** |

**btree 优势的条件**：数据量大 + 排布随机，min/max 失效时全扫 I/O 成本 > 索引查找开销。GIST 192MB×20=3.8GB 是临界点。
