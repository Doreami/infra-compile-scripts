# GIST1M 性能分析报告

> 2026-07-23, openEuler 24.03 / 96核 / 723GB
> GIST1M (960维), IVFPQ nc=256, uncompressed, fixed(3840)
> 表: `gist_ns.gist1m`, 索引: `idx_ivf_pq_vec`

## 一、当前性能

| 场景 | 耗时 (warm) | 说明 |
|------|:--:|------|
| IVF K=10 | **1,452ms** (1445-1460) | 5 轮平均，极稳定 |
| FullScan K=10 | **5,626ms** (5598-5662) | 3 轮平均 |
| IVF/FullScan 加速比 | **3.9x** | |

## 二、与历史基线对比

| 日期 | IVF K=10 | FullScan K=10 | 主要变更 |
|------|:--:|:--:|------|
| 7/17 | 7,031ms | 21,143ms | list\<float\>, zstd, nc=1024 |
| 7/21 | 19,764ms | 5,585ms | fixed, zstd→uncompressed, nc=256 |
| 7/22 | 18,775ms | 5,700ms | sparse row-take (buggy) |
| **7/23** | **1,452ms** | **5,626ms** | sparse 修复 + 基线优化 |

### 关键转折：IVF 从负优化到 3.9x 加速

```
7/17 (list+zstd):      IVF  7,031ms   FullScan 21,143ms   (3.0x, IVF 快)
7/21 (fixed+uncomp):   IVF 19,764ms   FullScan  5,585ms   (0.28x, IVF 慢!)
7/22 (sparse buggy):   IVF 18,775ms   FullScan  5,700ms   (0.30x, 仍然慢)
7/23 (sparse fixed):   IVF  1,452ms   FullScan  5,626ms   (3.9x, IVF 快!)
```

GIST 历史上 IVF 因并发缺失（`scan_single_file` 串行读文件）导致比 FullScan 慢 3.5x。sparse row-take 修复后，RowSelection 只解码候选行，I/O 量从全文件解码降为稀疏读取，IVF 逆转。

### FullScan 变迁

```
7/17 list+zstd        █████████████████████████████ 21,143ms
7/21 fixed+uncomp     ████████ 5,585ms    (-73.6%)
7/22 (基线)           ████████ 5,700ms
7/23 (基线)           ████████ 5,626ms    (-1.3% vs 7/22)
```

FullScan 在 fixed+uncomp 之后稳定在 ~5.6s，近期基线无明显变化。

## 三、与 SIFT 对比

| 指标 | SIFT (128d) | GIST (960d) | 比值 |
|------|:--:|:--:|:--:|
| IVF K=10 | 255ms | 1,452ms | **5.7x** |
| FullScan K=10 | 1,058ms | 5,626ms | **5.3x** |
| IVF/FullScan | 4.15x | 3.87x | |
| IVF 内核 I/O | 48% | 66% | 1.4x |
| IVF 索引搜索 | 3-5% | 4-5% | ~1x |

GIST 耗时约为 SIFT 的 5-6x，接近维度比（960/128=7.5x）和数据量比（3.6GB/500MB=7.2x）。IVF 加速比略低于 SIFT（3.9x vs 4.1x），因为 GIST 高维场景单候选 I/O 量更大。

## 四、关键结论

1. **GIST IVF 首次实现 <2s**：从 19s 降至 1.5s，12.9x 提升。sparse row-take 修复后首次在 GIST 上实现 IVF 快于 FullScan。

2. **高维场景 I/O 主导**：IVF 66% 时间在内核 I/O，远高于 SIFT 的 48%。后续优化重点在于减少每个候选的 I/O 量（列裁剪、更好的 page 级跳过）。

3. **索引搜索开销稳定**：960 维下仅 4-5%，与 128 维相近。聚类遍历的 CPU 成本相对固定，主要受 nc 影响而非维度。

4. **GIST 仍可优化**：当前 3.9x 加速比相对于 SIFT 的 4.1x 略低。原因是每个文件更大（192MB vs 7MB），即使 sparse take 后仍有较多 page 级 I/O。
