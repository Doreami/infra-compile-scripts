## 三、优化项贡献分析

### 3.1 iceberg-index 基线提交（7/22→7/23，影响 FullScan + IVF）

| 提交                 | 说明                                                                  |
| ------------------ | ------------------------------------------------------------------- |
| `ede582a`          | refactor: metadata execution caller-runtime driven                  |
| `8812f74`          | feat: accept FixedSizeBinary as vector column in IVF/IVF-PQ plugins |
| `ecbc6e8`          | perf: replace std HashMap with FxHashMap in reader.rs hot paths     |
| `d92091d` (bridge) | refactor: drive bridge async work on caller threads                 |

> 以上 4 个提交同时影响 FullScan 和 IVF，合计贡献 FullScan -9%（~110ms）。

### 3.2 IVF 专项优化

| 优化                  | 跨期        | 贡献    | 说明                                        |
| ------------------- |:---------:|:-----:| ----------------------------------------- |
| vector→fixed        | 7/17→7/21 | -42%  | 消除嵌套 Parquet 解码                           |
| zstd→uncompressed   | 7/21      | -10%  | 消除解压 CPU 开销                               |
| FxHash              | 7/21      | -2~6% | 消除 SipHash 热点                             |
| sparse row-take 修复  | 7/23      | 主要    | RowSelection 只解码候选行                       |
| `b5376c0` 性能优化(已修复) | 7/23      | 部分    | partial_sort、defer clone 等，revert 后保留部分优化 |

> 注：vector→fixed、uncompressed、FxHash 的贡献比例基于历史 A/B 测试，7/23 未单独复测。sparse row-take 是 7/22→7/23 IVF 大幅提升的**主要原因**。

## 四、IVF vs FullScan 分析

IVF 255ms vs FullScan 1058ms = 4.1x 加速。

```
IVF (255ms):
  索引搜索    ▏ ~13ms  (5%)
  Parquet I/O ████████████████ ~180ms (70%)
  gaussdb     ███ ~35ms (14%)
  其他        ██ ~27ms (11%)

FullScan (1058ms):
  Parquet I/O ███████████████████████████████ ~420ms (40%)
  缺页处理    █████████████ █ ~170ms (16%)
  L2 距离计算 ███████████ ~130ms (12%)
  行物化+排序 █████████████ ~150ms (14%)
  其他        ██████████████ ~188ms (18%)
```

## 五、关键结论

1. **IVF 首次实现 4x+ 加速比**：此前 SIFT 上 IVF 一直是负优化（~1,157ms vs FullScan ~1,163ms）。sparse row-take 修复 + uncompressed + fixed 组合使 IVF 降至 255ms，首次真正快于 FullScan。

2. **后续瓶颈**：内核 I/O 仍占 IVF 的 48%+，在 SIFT 小文件场景（20 文件 × 7MB）下优化空间有限。GIST 大文件（192MB/文件）sparse 收益更显著。

3. **FullScan 瓶颈在缺页和 L2 距离**：1,058ms 中 28% 是缺页+内核 I/O，12% 是距离计算。数据已在 page cache 后 FullScan 会显著加速。
