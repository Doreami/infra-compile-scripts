# 测试方法

> 2026-07-25

## 数据准备

### 分区表

- SIFT1M 和 GIST1M 分别导入到各自命名空间
- 使用 `setup_fixed.py` 脚本：读取 fvecs/HDF5 文件 → openGauss create_table → pyiceberg append
- 分区：`bucket[32]` on `id` 列，每分区一个 parquet 文件（单次 append 1M 行，Iceberg 自动按分区拆分写入 32 个文件）
- 每个 parquet 文件包含一个分区中约 31,250 行
- Parquet 压缩：ZSTD（pyiceberg 默认）

### 非分区表（SIFT 基线）

- SIFT1M 非分区表：10 次 append，每次 100K 行，产生 10 个 parquet 文件
- 每个文件包含约 100,000 行

### 索引构建

- 直接调用 `iceberg_catalog.create_index()` SQL 函数
- 参数：ivf_pq, num_clusters=256, sample_rate=100000
- SIFT (128 维): ~3 秒
- GIST (960 维): ~64 分钟（单线程 k-means + PQ 训练）

## 性能测试

使用 `bench_parallel.py` 脚本，核心流程：

1. 从表中读取 `id=1` 的行作为查询向量
2. 对每个 DOP 值，先执行 2 轮预热查询（warmup），再执行 5 轮计时查询
3. 每轮查询使用 `EXPLAIN ANALYZE`，从输出中提取 `Total runtime`
4. 检查查询计划中是否出现 `LOCAL GATHER` 以确认并行执行
5. IVF 测试：`SET enable_vectorsearch = on; SET try_vector_engine_strategy = force;`
6. FullScan 测试：关闭所有索引（enable_indexscan=off, enable_bitmapscan=off, enable_vectorsearch=off）
7. 不同 DOP 通过 `SET query_dop = N;` 设置

测试覆盖：

- DOP 值：1, 2, 4, 8, 16, 32
- K 值：10, 100, 10000
- 扫描类型：IVF 索引扫描、FullScan 全表扫描
- 表类型：非分区（基线）、32 分区

## 火焰图采集

使用 `run_flamegraph.py` 脚本，核心流程：

1. perf record 在目标 gaussdb 进程上以 99Hz 频率采样
2. 对每个场景执行预热查询后，再跑 2 轮查询并采集
3. 用 FlameGraph 工具链将 perf.data 转换为折叠栈 + SVG 火焰图
4. 所有场景均采集 IVF K=10000（计算密度最高，火焰图信息量最大）

## 数据完整性

- 所有 parquet 文件通过 `SELECT count(*)` 验证行数
- 分区表的 `bucket[32]` 保证了 32 个分区均有数据
- 索引构建后通过 `iceberg_catalog.table_indexes` 确认状态为 active
- 查询计划验证 `bridge vector index scan (hybrid task_group)` 确认走了索引
- 并行计划验证 `LOCAL GATHER` 确认了并行执行
