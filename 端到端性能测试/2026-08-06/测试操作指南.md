### 2.1 单列 BTree 范围查询测试

```bash
python3 -u btree_range_bench.py
```

- 覆盖 4 张表 (SIFT/GIST/DEEP/Synth)
- 5 种运算符 (=, >, >=, <, <=)
- 先测 FullScan（删索引），再测 Btree（建索引）
- 每轮 3 次预热 + 5 次计时取均值
- EXPLAIN 验证 BT 查询确实走 `bridge scalar index scan`

**主分支 (main) 结果**: Btree 全场景全败，Eq 慢 1.6-3.7x，范围慢 7-44x。

## 四、火焰图采集

```bash
PID=$(pgrep -x gaussdb | head -1)
perf record -g -p $PID -o /tmp/perf.data sleep 15 &
# 在 15s 窗口内循环跑查询...
perf script -i /tmp/perf.data | ~/FlameGraph/stackcollapse-perf.pl | ~/FlameGraph/flamegraph.pl > flame.svg
```

注意事项：
- `-p` 参数必须传 gaussdb 进程 PID（不是 bash 包装进程）
- 查询循环需填满采样窗口（避免 `LIMIT` 缩短查询时间）
- 之前采集失败是因为 `pgrep -f "gaussdb.*37000"` 匹配到了启动脚本的 bash 进程

## 五、多列表创建 (PyIceberg)

```python
from pyiceberg.schema import Schema
from pyiceberg.types import NestedField, IntegerType, StringType, DoubleType
from pyiceberg.catalog.sql import SqlCatalog
import pyarrow as pa

cat = SqlCatalog("multicol_cat", **{
    "uri": "sqlite:////tmp/multicol_cat.db",
    "warehouse": "file:///data/xl/warehouse/multicol"
})
cat.create_namespace("multicol_ns")
schema = Schema(
    NestedField(1, "id", IntegerType(), required=False),
    NestedField(2, "category", StringType()),
    NestedField(3, "score", DoubleType()),
)
tbl = cat.create_table("multicol_ns.t_multi", schema=schema)
batch = pa.table({...})
tbl.append(batch)
```

注册到 gaussdb:
```sql
SELECT iceberg_catalog.create_namespace('multicol_ns', '{}'::jsonb);
SELECT iceberg_catalog.register_table('multicol_ns','t_multi','file:///path/to/metadata.json');
CREATE FOREIGN TABLE multicol_ns.t_multi (...) SERVER iceberg_catalog_server OPTIONS (...);
```

## 六、常见踩坑

1. **pg_plugin 缓存**: 重编译 catalog/fdw 后需清空 `$GAUSSHOME/lib/postgresql/pg_plugin/` 中的 iceberg 相关文件并重启 gaussdb
2. **EXPLAIN 验证**: 每次测试前必须确认 EXPLAIN 输出 `bridge scalar index scan` 才说明走了索引
3. **perf PID**: 用 `pgrep -x gaussdb` 而非 `pgrep -f "gaussdb.*37000"`（后者会匹配到 bash）
4. **表名大小写**: gaussdb 中带引号的表名区分大小写，如 `"synth2048_10m"` 需用 `synth_ns."synth2048_10m"`
