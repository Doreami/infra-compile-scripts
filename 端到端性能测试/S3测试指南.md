## openGauss 配置

### FDW Server S3 选项

S3 存储通过 `iceberg_catalog_server` 的 server 级 OPTIONS 配置：

```sql
ALTER SERVER iceberg_catalog_server OPTIONS (
    SET warehouse 's3://xlperf-bucket/warehouse',
    ADD s3_endpoint 'http://172.168.22.25:19000',
    ADD s3_region 'us-east-1',
    ADD s3_access_key_id 'xlperf',
    ADD s3_secret_access_key 'PerfTest123!',
    ADD s3_path_style_access 'true',
    ADD s3_allow_http 'true'
);
```

FDW 根据 `s3://` 前缀自动选择 S3 后端，server 级选项传递端点、凭证给 bridge。

> 这些选项是 server 级别的，不是 foreign table 级别的。外表只需 `namespace` 和 `table_name`。

### 环境变量（catalog 端）

`openGauss-Catalog` 扩展读取如下环境变量（gaussdb 启动时需设置）：

```bash
export ICEBERG_WAREHOUSE='s3://xlperf-bucket/warehouse'
export ICEBERG_S3_ENDPOINT='http://172.168.22.25:19000'
export ICEBERG_S3_ACCESS_KEY='xlperf'
export ICEBERG_S3_SECRET_KEY='PerfTest123!'
export ICEBERG_S3_REGION='us-east-1'
```

> gaussdb 通过 `nohup` 启动时 `.bashrc` 不会自动加载，需在启动命令前显式 `env` 传递：
> ```bash
> env ICEBERG_WAREHOUSE='...' ... nohup gaussdb ...
> ```

## 建表与导数据

### 建表（SQL）

```sql
SELECT iceberg_catalog.create_namespace('sift_ns');
SELECT iceberg_catalog.create_table(
    'sift_ns', 'sift1m',
    '{"type":"struct","fields":[
        {"id":1,"name":"id","type":"long","required":true},
        {"id":2,"name":"vec","type":"fixed[512]","required":false,"vector_dim":128}
    ]}'::jsonb,
    's3://xlperf-bucket/warehouse/sift_ns/sift1m'
);
```

### 导数据（Python）

`setup_s3.py` — S3 版数据导入脚本，基于 `setup_fixed.py` 适配：

```bash
python3 setup_s3.py --input ~/测试文件/sift_base.fvecs --compression uncompressed
python3 setup_s3.py --input ~/测试文件/gist-960-euclidean.hdf5 --compression uncompressed
```

与本地版的关键差异：

| 项目 | 本地 (`setup_fixed.py`) | S3 (`setup_s3.py`) |
|------|------|------|
| warehouse | `file:///data/xl/warehouse` | `s3://xlperf-bucket/warehouse` |
| metadata 补丁 | `open(md_local)` 直接读写 | boto3 下载/上传 S3 |
| pyiceberg catalog | `warehouse=f"file://{warehouse}"` | S3 props + `py-io-impl` |
| 依赖 | pyiceberg, pyarrow | + boto3 |

### 建索引

```sql
SELECT iceberg_catalog.create_index(
    'sift_ns', 'sift1m', 'idx_ivf_pq_vec',
    '["vec"]'::jsonb, 'ivf_pq', 'ivf',
    '{"vector_column":"vec","num_clusters":256,"sample_rate":100000}'::jsonb

```

## 性能对比

测试条件：SIFT1M (128维), fixed(512), uncompressed, IVF nc=256, nprobe=10

| 场景 | 本地 FS | S3/MinIO | 比值 |
|------|:--:|:--:|:--:|
| IVF K=10 cold | 2,563ms | 12,808ms | 5.0x |
| IVF K=10 warm | 229ms | 1,010ms | 4.4x |
| IVF K=10000 warm | 291ms | 1,263ms | 4.3x |
| btree 点查 warm | 107ms | 133ms | 1.2x |

> S3 为本地网络 MinIO，延迟 ~1ms。远程 S3（10-50ms 延迟）下差距更大。

## 查询计时

与本地 FS 相同，使用墙钟法：

```bash
gsql=~/iceberg-og/openGauss-server-datainfra/mppdb_temp_install/bin/gsql
QVEC=$($gsql -d postgres -p 37000 -t -A -c "SELECT vec FROM sift_ns.sift1m WHERE id=1;")

# 预热
$gsql -d postgres -p 37000 -c "SET enable_vectorsearch=on; SELECT id FROM sift_ns.sift1m ORDER BY vec <-> '${QVEC}'::vector LIMIT 10;" > /dev/null

# 计时
for i in 1 2 3; do
  s=$(date +%s%3N)
  $gsql -d postgres -p 37000 -c "SET enable_vectorsearch=on; SELECT id FROM sift_ns.sift1m ORDER BY vec <-> '${QVEC}'::vector LIMIT 10;" > /dev/null
  e=$(date +%s%3N)
  echo "run$i: $((e-s))ms"
done
```

## 冷启动测试

`bench_all.py` 每个 K 值前有预热查询，不能用于冷启动测试。正确方式：**重启 gaussdb + 单次 EXPLAIN ANALYZE 计时**：

```bash
QV=$(gsql -p 37000 -d postgres -t -c "SELECT vec FROM s3_sift_ns.sift1m_s3 WHERE id=1;" | head -1)
pkill -9 -u xl gaussdb; sleep 2
nohup bash /tmp/start_gaussdb_s3.sh > /tmp/gaussdb.log 2>&1 & sleep 5
gsql -p 37000 -d postgres -c "SET enable_vectorsearch=on; SET try_vector_engine_strategy=force; EXPLAIN ANALYZE SELECT id FROM s3_sift_ns.sift1m_s3 ORDER BY vec <-> '${QV}'::vector LIMIT 10;" | grep "Total runtime"
```

## 注意事项

- S3 查询首次超时可能是 gaussdb 未拿到 S3 环境变量，检查 `/proc/$PID/environ` 确认
- MinIO 本地网络延迟极低（<1ms），缓存优化的墙钟收益在 S3 上同样被噪声掩盖
- `setup_s3.py` 依赖 boto3 读写 S3 metadata，需先 `pip3 install boto3`
- 本地 FS 和 S3 表可共存，通过不同 namespace 区分（如 `s3_sift_ns` vs `sift_ns`）
- S3 表推荐用 `setup_s3.py --namespace s3_xxx_ns --table xxx_s3` 避免与本地表冲突
- 切换 S3 需 `ALTER SERVER iceberg_catalog_server OPTIONS (ADD s3_endpoint '...', ...)` 配置连接参数，再用 `ICEBERG_WAREHOUSE=s3://...` 启动 gaussdb
- 编译新 `.so` 后必须重启 gaussdb，否则 dlopen 加载新老符号冲突导致 segfault
