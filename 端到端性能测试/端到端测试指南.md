### 3.3 `setup_fixed.py` 参数说明

| 参数                    | 默认值            | 说明                                       |
| --------------------- | -------------- | ---------------------------------------- |
| `--input`             | 必填             | 数据文件（`.fvecs` / `.hdf5` / `.fbin`）       |
| `--namespace`         | 自动推断           | 如 `sift_ns`                              |
| `--table`             | 自动推断           | 如 `sift1m`                               |
| `--chunk-size`        | 50000          | 每批次写入行数 = 每文件行数 = RowGroup 行数（三合一，见下方说明） |
| `--partition-buckets` | 0              | >0 创建 `bucket(id, N)` 分区                 |
| `--vec-type`          | `list`         | `list`=list<float>, `fixed`=fixed binary |
| `--compression`       | `uncompressed` | Parquet 压缩方式                             |
| `--max-rows`          | None           | 截取行数（cropped fbin）                       |

> 脚本自动：建表 → ALTER type（如需要）→ 导数据 → 更新元数据。无需手动干预。
>
> **`--chunk-size` 说明**：pyiceberg 每次 `tbl.append()` 产生 1 个 parquet 文件（含 1 个 RowGroup）。
>
> | 模式 | 每轮行数 | 每分区每文件行数 | 总文件数 |
> |------|----------|-----------------|----------|
> | 无分区 | chunk_size | — | ≈ N / chunk_size |
> | 分区 K 个 | chunk_size × K | ≈ chunk_size | ≈ K × N / (chunk_size × K) = N / chunk_size |
>
> 两种模式每文件行数都约等于 chunk_size，总文件数也相同，区别仅在于分区表文件分散到 K 个分区目录。
> 目前无法独立控制文件数和 RowGroup 大小（一个 append = 一个文件 = 一个 RG），这是 pyiceberg 的限制。
>
> **chunk_size 过大还会触发 int32 溢出**：Arrow `ListArray` 将所有行的 float 值平铺为连续 buffer，offsets 用 int32。当 `outer_step × dim > 2^31` 时溢出。高维数据（如 2048 维）需减小 chunk_size 使 `outer_step × dim < 2^31`。脚本已自动检测并切换 LargeListArray（int64），但建议 chunk_size 控制在安全范围内。

### 4.1 索引构建耗时参考

| 数据集     | 行数    | 维度   | 预计耗时    |
| ------- | ----- | ---- | ------- |
| SIFT    | 100万  | 128  | ~4 分钟   |
| GIST    | 100万  | 960  | ~31 分钟  |
| DEEP-1B | 10亿   | 96   | ~4.5 小时 |
| Synth   | 1000万 | 2048 | ~1.5 小时 |

> `sample_rate=100000` 时训练采样上限 = min(1024×100000, 100000) = 10 万向量，四表一致

### 4.2 调参提高召回率

除了增大 `nprobe`，还可以调整索引构建参数：

**`num_clusters`**（聚类数，默认 256）

| 增大  | 效果                                     |
| --- | -------------------------------------- |
| ✅   | 每个簇更小更纯，相同 nprobe 覆盖更多数据 → 召回提高        |
| ❌   | 索引变大，构建更慢。过大时簇内点数太少，K-Means 不稳定        |
| 建议  | 1M 行以下 ≤1024，10M 行可到 4096，1B 行 1024 已够 |

**`sample_rate`**（K-Means 训练采样倍率，默认 256）

```
实际训练样本数 = min(num_clusters × sample_rate, 100000)
```

| sample_rate | num_clusters=256 | num_clusters=1024 |
| ----------- | ---------------- | ----------------- |
| 256（默认）     | 65,536           | 100,000（触及上限）     |
| 100         | 25,600           | 100,000（触及上限）     |
| 10          | 2,560（可能欠拟合）     | 10,240            |

> `sample_rate` 太小 → K-Means 欠拟合，聚类质量差，召回下降。
> 触及 100K 上限后继续增大无意义。
> 对 10 亿行表，100K 仅占 0.01%，这是大表召回率偏低（30%）的根本原因之一。

### 5.5 手动查询

**获取 query 向量**（官方 query 文件，非表内 id=1）：

```bash
# SIFT（fvecs 格式）
python3 -c "
import struct
with open('sift_query.fvecs','rb') as f:
    data = f.read()
dim = struct.unpack_from('<i', data, 0)[0]

"

# GIST（HDF5 格式）
python3 -c "
import h5py
with h5py.File('gist-960-euclidean.hdf5','r') as f:

"

# DEEP / Synth（fbin 格式，读取第一条查询）
python3 -c "
import struct
with open('query.public.10K.fbin','rb') as f:
    nq = struct.unpack('<i', f.read(4))[0]
    dim = struct.unpack('<i', f.read(4))[0]
    f.seek(8)
    vec = struct.unpack(f'<{dim}f', f.read(dim * 4))
print('[' + ','.join(str(v) for v in vec) + ']')
"
```

**查询语句**：

```sql
-- IVF 索引扫
SET query_dop = 8;
SET enable_vectorsearch = on;
EXPLAIN ANALYZE SELECT id FROM <ns>.<tbl>
  ORDER BY vec <-> '[...]'::vector LIMIT 10;

-- FullScan
SET query_dop = 8;
SET enable_vectorsearch = off;
EXPLAIN ANALYZE SELECT id FROM <ns>.<tbl>
  ORDER BY vec <-> '[...]'::vector LIMIT 10;
```

> **重要**：用 `Total runtime` 行做计时（含 bridge I/O），不能用 `actual time`（仅 gaussdb executor）
> **注意**：向量字面量很长时，`-c` 可能截断，建议写 SQL 文件后用 `-f` 执行

## 六、召回率测试

### 6.1 使用官方 Ground Truth

```bash
# SIFT：官方 groundtruth.ivecs + 官方 query 文件
python3 -c "
import struct, subprocess, os

# 加载 ground truth（0-based → +1 转 gaussdb 1-based）
f = open('sift_groundtruth.ivecs', 'rb')
K = struct.unpack('<i', f.read(4))[0]
gt_ids = struct.unpack('<%dI' % K, f.read(K * 4))
f.close()

# 加载 query 向量（官方 query 文件）
f2 = open('sift_query.fvecs', 'rb')
dim = struct.unpack_from('<i', f2.read(4), 0)[0]
f2.seek(4)
vec = struct.unpack('<%df' % dim, f2.read(dim * 4))
f2.close()
qv = '[' + ','.join(str(v) for v in vec) + ']'

# 跑 IVF 查询
GSQL = os.environ['GAUSSHOME'] + '/bin/gsql'
for k in [10, 100]:
    sql = f\"SET enable_vectorsearch=on; SELECT id FROM sift_ns.sift1m ORDER BY vec <-> '{qv}'::vector LIMIT {k};\"
    r = subprocess.run([GSQL, '-d', 'postgres', '-p', '37000', '-c', sql],
                       capture_output=True, text=True)
    ivf_ids = [int(l.strip()) for l in r.stdout.split('\\n') if l.strip().isdigit()]
    gt = set(i + 1 for i in gt_ids[:k])
    recall = len(gt & set(ivf_ids[:k])) / k
    print(f'Recall@{k} = {recall:.1%}')
"
```

### 6.2 DEEP 同理

```python
# 使用官方 deep_new_groundtruth.public.10K.bin
# 格式：[nq: uint32][K: uint32][nq*K*uint32 IDs]
f = open('deep_new_groundtruth.public.10K.bin', 'rb')
nq = struct.unpack('<I', f.read(4))[0]
K = struct.unpack('<I', f.read(4))[0]
gt_ids = struct.unpack('<%dI' % (nq * K), f.read(nq * K * 4))
# gt_ids[q * K + i] 是查询 q 的第 i 个邻居（0-based）
```

### 6.3 无官方 GT 时

用 FullScan K=10000 结果作为自洽验证基准（非真实外部召回，报告中需标注）：

```sql
SET enable_vectorsearch=off;
```

### 6.4 Ground Truth 文件清单

| 数据集 | GT 文件 | 查询数 | K | 格式 | 备注 |
|--------|---------|--------|---|------|------|
| SIFT | `sift_groundtruth.ivecs` | 10000 | 100 | ivecs | per-entry `[K:int32][ids:int32*K]`，0-based |
| GIST | HDF5 内嵌 `neighbors` | 1000 | 100 | HDF5 | `gist-960-euclidean.hdf5` 的 `neighbors` 数据集 |
| DEEP | `deep_new_groundtruth.public.10K.bin` | 10000 | 100 | bin | `[nq:uint32][K:uint32][ids:**uint64***nq*K]`，注意是 uint64！ |
| Synth | `gen_groundtruth.py` 生成 | 自定义 | 自定义 | bin | `[nq:uint32][K:uint32][ids:uint32*nq*K]` |

> **DEEP uint64 陷阱**：文件 8,000,008 字节，每个 ID 占 8 字节（uint64），不是 4 字节（uint32）。虽然实际 ID 值在 uint32 范围内（<10 亿），但解析时必须按 uint64 读取取低 32 位。
>
> **召回率计算必须用 `-f` 文件**：query 向量字面量很长，`gsql -c` 可能截断，导致 IVF 返回空或错误结果。始终写 SQL 文件后用 `-f` 执行。

## 七、火焰图采集

### 7.1 手动采集（推荐，最可靠）

```bash
PID=$(pgrep -u $USER -x gaussdb)
OUTDIR=~/flamegraphs_$(date +%Y-%m-%d)
mkdir -p $OUTDIR

# 预热
gsql -d postgres -p 37000 -c "${SETUP} SELECT id FROM ${TBL} ORDER BY vec <-> '${QV}'::vector LIMIT ${K};" > /dev/null

# 起 perf 后台录制
perf record -F 99 -g -p $PID -o ${OUTDIR}/perf_${LABEL}.data -- sleep 999 &
PFPID=$!
sleep 1

# 跑查询（轮数根据查询耗时调整：快查询 10-20 轮，慢查询 2-3 轮）
for i in $(seq 1 $ROUNDS); do
  gsql -d postgres -p 37000 -c "${SETUP} SELECT id FROM ${TBL} ORDER BY vec <-> '${QV}'::vector LIMIT ${K};" > /dev/null
done

# 停 perf + 生成 SVG
kill $PFPID; wait $PFPID
perf script -i ${OUTDIR}/perf_${LABEL}.data \
  | ~/FlameGraph/stackcollapse-perf.pl \
  | ~/FlameGraph/flamegraph.pl --title "${LABEL}" --width 1200 --colors hot \
  > ${OUTDIR}/flame_${LABEL}.svg
```

### 7.2 采集清单

```
每个数据集采集：
  - IVF K=10/100/1000/10000 DOP=1
  - IVF K=10/100/1000/10000 DOP=8
  - FullScan K=10 DOP=1
```

### 7.3 注意事项

| 事项                      | 说明                                   |
| ----------------------- | ------------------------------------ |
| 快查询（<500ms）             | 多跑几轮（10-20），保证 >200 samples          |
| 慢查询（>10s）               | 2-3 轮即可，perf sleep 要覆盖查询时长           |
| `perf_event_paranoid`   | 设为 -1，否则 perf 无权限                    |
| 不要 source opengauss.env | 会污染 LD_LIBRARY_PATH 导致 perf 失败       |
| 用 `pgrep -x gaussdb`    | 不要用 `pgrep -f gaussdb`（会匹配到 wrapper） |

```sql
-- 设置 nprobe（需 FDW 支持，参考 PR #33）
-- 注意：ADD 在选项已存在时静默失败，必须先 DROP 再 ADD
ALTER FOREIGN TABLE synth_ns.synth2048v_10m OPTIONS (DROP nprobe);
ALTER FOREIGN TABLE synth_ns.synth2048v_10m OPTIONS (ADD nprobe '50');

-- 查询时自动生效
SET enable_vectorsearch = on;
SELECT id FROM synth_ns.synth2048v_10m ORDER BY vec <-> '...'::vector LIMIT 10;

-- 恢复默认
ALTER FOREIGN TABLE synth_ns.synth2048v_10m OPTIONS (DROP nprobe);
ALTER FOREIGN TABLE synth_ns.synth2048v_10m OPTIONS (ADD nprobe '10');
```

> 增大 nprobe 提高召回但增加耗时。Synth nprobe=100 召回从 0%→70%，耗时 2.5×。

## 十、常见问题

| 问题                       | 解决方法                                                    |
| ------------------------ | ------------------------------------------------------- |
| `list<float>` 映射为 `text` | schema JSON 加 `"vector_dim": N` 字段                      |
| 表名大小写问题                  | 统一用小写表名                                                 |
| `Too many open files`    | `ulimit -n 65536` 后重启 gaussdb                           |
| perf 报权限错误               | 不要 `source opengauss.env`，用绝对路径                         |
| 编译 FDW 报头文件缺失            | `ln -sf openGauss-server-datainfra ../openGauss-server` |
| DOP 不生效                  | 确认表有分区（`bucket[32]`），无分区表 DOP 无效                        |
| 索引构建时查询变慢                | 索引构建占用 CPU，等构建完成后再测                                     |
| 删除表报锁超时                  | 先 `pg_terminate_backend` 杀掉阻塞的查询                        |
| IVF 不走索引                 | query 向量必须用字面量，不能用子查询                                   |
