## 构建测试数据

Iceberg 表**不支持 INSERT**，数据通过以下方式导入。

### 建表

通过 Catalog 接口创建托管表（由 `iceberg_catalog.create_table` 管理）：

```sql
CREATE EXTENSION iceberg_catalog;
CREATE EXTENSION iceberg_fdw;

-- 创建 namespace（也会创建对应的 openGauss schema）
SELECT iceberg_catalog.create_namespace('myns', '{}'::jsonb);

-- 建表：定义列名、类型、是否必填
SELECT iceberg_catalog.create_table(
    'myns', 'users',
    '{"type":"struct","fields":[
      {"id":1,"name":"id","type":"long","required":true},
      {"id":2,"name":"name","type":"string","required":false},
      {"id":3,"name":"age","type":"int","required":false},
      {"id":4,"name":"desc","type":"string","required":false}
    ]}'::jsonb
);
```

**支持的列类型**：`int`, `long`, `float`, `double`, `string`, `boolean`, `date`, `timestamp`, `decimal`, `binary`，以及 `list` / `map` / `struct` 嵌套类型。

### 查询确认

```sql
-- 查看表是否存在
SELECT namespace, table_name, metadata_location IS NOT NULL AS has_metadata
FROM iceberg_catalog.tables_internal
WHERE namespace = 'myns';

-- 查看表结构
SELECT field_id, field_name, field_type, field_required
FROM iceberg_catalog.table_schemas
WHERE table_uuid = (
    SELECT table_uuid FROM iceberg_catalog.tables_internal
    WHERE namespace = 'myns' AND table_name = 'users'
)
ORDER BY field_id;

-- 查询表数据（刚建表时为空）
SELECT * FROM myns.users;
```

### 导入数据

#### 方式一：直接写入 Parquet 文件到 warehouse

```bash
# warehouse 目录结构：
#   $ICEBERG_WAREHOUSE/
#     myns.db/
#       users/
#         data/         # 数据文件（Parquet 格式）
#           xxx.parquet
#         metadata/     # 元数据文件（由 Catalog 管理）

# 用 Spark/PyArrow 生成 Parquet 文件放到对应位置
# Spark 示例：
#   df.write.format("parquet").save(f"{warehouse}/myns.db/users/data/")
```

#### 方式二：使用 Spark / Flink 写入

Iceberg 表支持通过 Spark/Flink 引擎写入数据，写入后 openGauss 通过 fdw 即可查询。

#### 方式三：使用 PyArrow 生成测试数据（手动）

```python
import pyarrow as pa
import pyarrow.parquet as pq
import os

warehouse = os.path.expanduser("/data/xl/warehouse")
table_path = f"{warehouse}/myns.db/users/data"

# 生成 Parquet 文件
schema = pa.schema([
    ("id", pa.int64(), False),
    ("name", pa.string(), True),
    ("age", pa.int32(), True),
    ("desc", pa.string(), True),
])
data = [
    (1, "Alice", 28, "Engineer"),
    (2, "Bob",   35, "Manager"),
    (3, "Carol", 30, "Designer"),
]
t = pa.table(data, schema=schema)
os.makedirs(table_path, exist_ok=True)
pq.write_table(t, f"{table_path}/sample.parquet")

print(f"Written to {table_path}/sample.parquet")
```

写入后 openGauss 端即可查询：

```sql
SELECT * FROM myns.users;
```

#### 方式四：使用 import_csv.py 导入 CSV（推荐）

通过通用导入脚本一键导入 CSV 文件，自动管理 Iceberg 元数据和 openGauss catalog：

```bash
# 创建表并导入数据
python3 导入数据/import_csv.py --op create --csv data.csv \
  -n myns -t users \
  -c "id:long,name:string,age:int,desc:string" \
  -w /data/xl/warehouse --gsql "gsql -d postgres -p 37000"

# 追加数据
python3 导入数据/import_csv.py --op insert --csv new_data.csv \
  -n myns -t users \
  -c "id:long,name:string,age:int,desc:string" \
  -w /data/xl/warehouse --gsql "gsql -d postgres -p 37000"
```

支持 create / insert / update / delete / drop 五种操作，详见 `导入数据/使用示例.md`。

### 向量数据

对于向量索引测试，需要包含 `list<float>` 类型的列：

```sql
SELECT iceberg_catalog.create_table(
    'myns', 'vectors',
    '{"type":"struct","fields":[
      {"id":1,"name":"id","type":"long","required":true},
      {"id":2,"name":"vec","type":{"type":"list","element-id":3,"element":"float","element-required":true},"required":false}
    ]}'::jsonb
);
```

用 PyArrow 生成向量数据的 Parquet：

```python
import pyarrow as pa
import pyarrow.parquet as pq
import numpy as np

warehouse = os.path.expanduser("/data/xl/warehouse")

# 128 维向量，3 条记录
dim = 128
num_rows = 3
vectors = np.random.randn(num_rows, dim).astype(np.float32)

schema = pa.schema([
    ("id", pa.int64(), False),
    ("vec", pa.list_(pa.float32()), False),
])
t = pa.table({
    "id": [1, 2, 3],
    "vec": [vectors[0].tolist(), vectors[1].tolist(), vectors[2].tolist()],
}, schema=schema)

os.makedirs(f"{warehouse}/myns.db/vectors/data", exist_ok=True)
pq.write_table(t, f"{warehouse}/myns.db/vectors/data/vecs.parquet")
```

## 运行测试

### 全部测试（devtest 回归套件）

```bash
cd ~/infra-compile-scripts
bash run_test.sh
```

首次运行会自动 clone `DataInfra-devtest` 测试仓库到 `~/iceberg-og/`。

常用参数（透传给 devtest runner）：

| 参数 | 说明 |
|------|------|
| `--stop-on-failure` | 遇到失败立即停止 |
| `--keep-temp` | 保留临时数据库实例，便于排查 |
| `--case <name>` | 仅运行指定用例 |

```bash
# 只跑一个用例，失败即停、保留现场
bash run_test.sh --case 02_catalog_namespace --stop-on-failure --keep-temp
```

### 单独跑 fdw 测试

```bash
GAUSSHOME=~/iceberg-og/openGauss-server-datainfra/mppdb_temp_install
export LD_LIBRARY_PATH=$GAUSSHOME/lib:$GAUSSHOME/lib/postgresql:$LD_LIBRARY_PATH
export ICEBERG_WAREHOUSE=file:///data/xl/warehouse
PORT=37000  # 你的 gaussdb 端口

for test in managed_ddl managed_scan vectorsearch_iceberg; do
    db="fdw_$test"
    $GAUSSHOME/bin/gsql -X -q -p $PORT -d postgres -c "DROP DATABASE IF EXISTS \"$db\";"
    $GAUSSHOME/bin/gsql -X -q -p $PORT -d postgres -c "CREATE DATABASE \"$db\";"
    echo "=== $test ==="
    $GAUSSHOME/bin/gsql -X -a -q -v ON_ERROR_STOP=1 -p $PORT -d "$db" \
        -f ~/iceberg-og/iceberg_fdw/sql/$test.sql
    $GAUSSHOME/bin/gsql -X -q -p $PORT -d postgres -c "DROP DATABASE IF EXISTS \"$db\";"
done
```

## 添加测试用例

### 方式一：devtest 回归套件（推荐——自动管理数据库实例）

在 `~/iceberg-og/DataInfra-devtest/test/` 目录下添加文件：

```
test/
├── sql/                          # SQL 测试文件
│   ├── 01_basic_opengauss.sql
│   ├── 02_catalog_namespace.sql
│   ├── catalog/                  # 按模块分目录
│   │   ├── 04_phase1_remove_orphan_files.sql
│   │   └── 05_phase1_maintenance_e2e.sql
│   └── delta/
│       ├── 03_run_tests.sql
│       └── 06_delta_flush.sql
├── expected/                     # 期望输出（同名 .out）
│   ├── 01_basic_opengauss.out
│   ├── catalog/
│   │   └── 04_phase1_remove_orphan_files.out
│   └── delta/
│       └── 06_delta_flush.out
└── schedules/
    └── serial_schedule           # 用例列表
```

**步骤：**

1. **编写 SQL 测试文件**（放在 `sql/` 下）

```sql
-- sql/my_test.sql
CREATE EXTENSION IF NOT EXISTS iceberg_catalog;
CREATE EXTENSION IF NOT EXISTS iceberg_fdw;

SELECT iceberg_catalog.create_namespace('myns', '{}'::jsonb) IS NOT NULL AS ok;

SELECT iceberg_catalog.create_table(
    'myns', 'my_table',
    '{"type":"struct","fields":[
      {"id":1,"name":"id","type":"long","required":true},
      {"id":2,"name":"val","type":"string","required":false}
    ]}'::jsonb
);

SELECT * FROM myns.my_table;
```

2. **生成期望输出**

```bash
cd ~/infra-compile-scripts
GAUSSHOME=~/iceberg-og/openGauss-server-datainfra/mppdb_temp_install
$GAUSSHOME/bin/gsql -X -a -q -p 37000 -d postgres \
    -f ~/iceberg-og/DataInfra-devtest/test/sql/my_test.sql \
    > ~/iceberg-og/DataInfra-devtest/test/expected/my_test.out 2>&1
```

3. **编辑期望输出** — 去掉路径和 `total time` 行：

```bash
sed -i -E \
    -e 's#gsql:.*/([^/[:space:]]+\.sql):#gsql:\1:#g' \
    -e '/^total time:/d' \
    ~/iceberg-og/DataInfra-devtest/test/expected/my_test.out
```

4. **注册到调度文件** `schedules/serial_schedule`：

```
test: my_test
```

5. **验证**

```bash
bash run_test.sh --case my_test --stop-on-failure --keep-temp
```

### 方式二：fdw 独立测试（适合快速验证 fdw 功能）

1. 在 `~/iceberg-og/iceberg_fdw/sql/` 下添加 `.sql` 文件
2. 运行并生成期望输出到 `~/iceberg-og/iceberg_fdw/expected/`（同名 `.out`）
3. 以上面的 "单独跑 fdw 测试" 脚本验证

### SQL 测试编写要点

- 每个 SQL 文件是一个独立测试用例，在隔离的数据库中运行
- **首条 SQL 必须是 `CREATE EXTENSION`**，因为每个测试数据库是全新的
- 用 `ON_ERROR_STOP=1` 会在第一条语句失败时停止
- 避免依赖全局变量或硬编码路径
- 测试完成后 `DROP DATABASE` 清理

### 常见失败原因

| 现象 | 原因 | 解决 |
|------|------|------|
| `could not open extension control file` | 扩展 .control 文件未安装到 GAUSSHOME | 确认 `setup.sh` 已成功执行 |
| 输出有 `NOTICE: extension already exists` | 第二次运行未重建数据库 | 每次都 `CREATE DATABASE` 新库 |
| 期望/实际 diff 看起来相同 | 路径格式或末尾空白差异 | 检查 `sed` 标准化步骤是否一致 |
| gsql exit 2 | 连接失败 | 确认 gaussdb 在运行且端口正确 |
