# 测试指南

## 前置条件

1. `setup.sh` 已成功执行（编译完成）
2. gaussdb 实例已启动（参考 [README.md](./README.md#6-init--start-db) 第 6 节）

```bash
export ICEBERG_WAREHOUSE=file://$HOME/warehouse
gs_initdb -D ~/ogdata --nodename=primary
gaussdb -D ~/ogdata -p 37000 --single_node &
```

## 运行测试

### 全部测试（devtest 回归套件）

```bash
cd ~/infra-compile-scripts
bash run_test.sh
```

首次运行会自动 clone `DataInfra-devtest` 测试仓库到 `~/iceberg-og/`。

常用参数（透传给 devtest runner）：

| 参数 | 说明 |
|------|------|
| `--stop-on-failure` | 遇到失败立即停止 |
| `--keep-temp` | 保留临时数据库实例，便于排查 |
| `--case <name>` | 仅运行指定用例 |

```bash
# 只跑一个用例，失败即停、保留现场
bash run_test.sh --case 02_catalog_namespace --stop-on-failure --keep-temp
```

### 单独跑 fdw 测试

```bash
GAUSSHOME=~/iceberg-og/openGauss-server-datainfra/mppdb_temp_install
export LD_LIBRARY_PATH=$GAUSSHOME/lib:$GAUSSHOME/lib/postgresql:$LD_LIBRARY_PATH
export ICEBERG_WAREHOUSE=file://$HOME/warehouse
PORT=37000  # 你的 gaussdb 端口

for test in managed_ddl managed_scan vectorsearch_iceberg; do
    db="fdw_$test"
    $GAUSSHOME/bin/gsql -X -q -p $PORT -d postgres -c "DROP DATABASE IF EXISTS \"$db\";"
    $GAUSSHOME/bin/gsql -X -q -p $PORT -d postgres -c "CREATE DATABASE \"$db\";"
    echo "=== $test ==="
    $GAUSSHOME/bin/gsql -X -a -q -v ON_ERROR_STOP=1 -p $PORT -d "$db" \
        -f ~/iceberg-og/iceberg_fdw/sql/$test.sql
    $GAUSSHOME/bin/gsql -X -q -p $PORT -d postgres -c "DROP DATABASE IF EXISTS \"$db\";"
done
```

## 添加测试用例

### 方式一：devtest 回归套件（推荐——自动管理数据库实例）

在 `~/iceberg-og/DataInfra-devtest/test/` 目录下添加文件：

```
test/
├── sql/                          # SQL 测试文件
│   ├── 01_basic_opengauss.sql
│   ├── 02_catalog_namespace.sql
│   ├── catalog/                  # 按模块分目录
│   │   ├── 04_phase1_remove_orphan_files.sql
│   │   └── 05_phase1_maintenance_e2e.sql
│   └── delta/
│       ├── 03_run_tests.sql
│       └── 06_delta_flush.sql
├── expected/                     # 期望输出（同名 .out）
│   ├── 01_basic_opengauss.out
│   ├── catalog/
│   │   └── 04_phase1_remove_orphan_files.out
│   └── delta/
│       └── 06_delta_flush.out
└── schedules/
    └── serial_schedule           # 用例列表
```

**步骤：**

1. **编写 SQL 测试文件**（放在 `sql/` 下）

```sql
-- sql/my_test.sql
CREATE EXTENSION IF NOT EXISTS iceberg_catalog;
CREATE EXTENSION IF NOT EXISTS iceberg_fdw;

SELECT iceberg_catalog.create_namespace('myns', '{}'::jsonb) IS NOT NULL AS ok;

SELECT iceberg_catalog.create_table(
    'myns', 'my_table',
    '{"type":"struct","fields":[
      {"id":1,"name":"id","type":"long","required":true},
      {"id":2,"name":"val","type":"string","required":false}
    ]}'::jsonb
);

SELECT * FROM myns.my_table;
```

2. **生成期望输出**

```bash
cd ~/infra-compile-scripts
GAUSSHOME=~/iceberg-og/openGauss-server-datainfra/mppdb_temp_install
$GAUSSHOME/bin/gsql -X -a -q -p 37000 -d postgres \
    -f ~/iceberg-og/DataInfra-devtest/test/sql/my_test.sql \
    > ~/iceberg-og/DataInfra-devtest/test/expected/my_test.out 2>&1
```

3. **编辑期望输出** — 去掉路径和 `total time` 行：

```bash
sed -i -E \
    -e 's#gsql:.*/([^/[:space:]]+\.sql):#gsql:\1:#g' \
    -e '/^total time:/d' \
    ~/iceberg-og/DataInfra-devtest/test/expected/my_test.out
```

4. **注册到调度文件** `schedules/serial_schedule`：

```
test: my_test
```

5. **验证**

```bash
bash run_test.sh --case my_test --stop-on-failure --keep-temp
```

### 方式二：fdw 独立测试（适合快速验证 fdw 功能）

1. 在 `~/iceberg-og/iceberg_fdw/sql/` 下添加 `.sql` 文件
2. 运行并生成期望输出到 `~/iceberg-og/iceberg_fdw/expected/`（同名 `.out`）
3. 以上面的 "单独跑 fdw 测试" 脚本验证

### SQL 测试编写要点

- 每个 SQL 文件是一个独立测试用例，在隔离的数据库中运行
- **首条 SQL 必须是 `CREATE EXTENSION`**，因为每个测试数据库是全新的
- 用 `ON_ERROR_STOP=1` 会在第一条语句失败时停止
- 避免依赖全局变量或硬编码路径
- 测试完成后 `DROP DATABASE` 清理

### 常见失败原因

| 现象 | 原因 | 解决 |
|------|------|------|
| `could not open extension control file` | 扩展 .control 文件未安装到 GAUSSHOME | 确认 `setup.sh` 已成功执行 |
| 输出有 `NOTICE: extension already exists` | 第二次运行未重建数据库 | 每次都 `CREATE DATABASE` 新库 |
| 期望/实际 diff 看起来相同 | 路径格式或末尾空白差异 | 检查 `sed` 标准化步骤是否一致 |
| gsql exit 2 | 连接失败 | 确认 gaussdb 在运行且端口正确 |
