## 一、要解决的问题

**标量过滤 + 向量相似度 Top-K** 查询：

```sql
SELECT id FROM tab
WHERE category = 'electronics'
ORDER BY vec <-> '<query_vector>'::vector
LIMIT 10;
```

### 现状（代码逐条核实，设计 §1.3 全部属实）

当前是 **post-filter（检索后过滤）**：

| 环节 | 现状 | 代码位置 |
|---|---|---|
| 路由 | 向量/标量路径**互斥**，含标量只走向量路径 | `iceberg_fdw.cpp:1628`、`profile_kind` 三选一 `iceberg_fdw.h:148` |
| 标量过滤 | 文件级谓词下推 + FDW 本地 recheck，不进向量检索 | `scan_options.filter_json` |
| 召回兜底 | 内核 `FetchK = TopK×5`，夹 `[50, 10000]` | `planvectorsearch.cpp:28-30`、`compute_fetch_k` :79 |
| 物化 | 候选行全量物化（Parquet 读 + Arrow 解码），最大耗时 | — |

实测基线：

| 数据集 | 纯 IVF K=10 (DOP1/8) | 全扫 K=10 | 官方召回@10 |
|---|---|---|---|
| SIFT | 212ms / 63ms | 2358ms | 90.6% |
| GIST | 1467ms / 311ms | 18883ms | 78.4% |

**痛点**：① 高选择率下 FetchK 兜底召回无保证（可能静默返回空）；② 全部候选行全量物化，物化是最大耗时。

### SQL 语法口径（已核实）

真实接口是 `ORDER BY vec <-> '<q>'::vector LIMIT K`（`vectorsearch_iceberg.sql:38`、`eval_recall.py:181` 核实一致 ✅）。

## 二、核心思路

**把标量条件从「检索后过滤」前移为「检索内预过滤」，按选择率自动在三档间路由。复用现有索引，不改变索引存储格式。**

```
查询
  ▼
① 文件级裁剪（第零级，现状保留）   Iceberg 文件级谓词 → 排除不可能匹配的数据文件
  ▼
② 行级预过滤（本次新增）           标量 BTree 计数/枚举 → 候选行集合 → 向量检索只在该集合内出候选
  ▼
③ 物化                          只剩命中标量的候选行 → 直击「物化是最大耗时」瓶颈
```

业界对齐（调研报告）：所有成熟系统都在做查询期自适应——不存在全局最优方案，最优由「过滤选择性 + 过滤-向量相关性 + K + 数据分布」共同决定。三档路由正是这一共识的落地。

## 四、关键现实：全局单索引，不是 per-file

设计曾假设「IVFPQ 按文件组织（per-file IVF，Lance footer 模式）」，**代码现状不符**，已订正：

- IVFPQ 是**全局单索引空间**：一个 segment 一个工件，IVF 分区跨多个数据文件，每行记 `file_indices: Vec<u32>`（`ivf_pq.rs:14` "single binary file per segment"、`:189`）。
- 标量 BTree 同为全局索引。

**设计影响**（§5.2 已重写）：
- 「按文件覆盖组合分区执行」→ 实际是**行级过滤策略按文件分组**，非物理 per-file 子索引。
- 受限搜索在**全局索引内循环逐行过滤**：分区内逐行算 ADC 距离时，该行 `file_index` 所属文件在「标量∩向量覆盖」掩码内 → 先查行级候选位图、命中才算距离；在「仅向量覆盖」掩码内 → 不过滤（退化为现状，事后 recheck）。
- 与 Lance 差异：Lance footer IVF 按文件组织（文件剪枝栈可直接裁剪）；本方案走 Iceberg 文件级谓词（第零级）+ 全局索引内循环过滤。

## 五、三级路由（设计核心）

路由判定用**组合估算**（count-only，不枚举），不用组合枚举——判「宽」就得白跑完整标量检索，与「回退后过滤」自相矛盾。**估算只允许做上界**：宁可把「可能小」判成小，不把「其实小」判成大（大档有运行时护栏兜底）。

判定由廉价到昂贵递进，每层触顶截断：

```
0. 文件级预判（免费）
   存活占比 > 90%  → 后过滤（现状），连索引都不碰
   存活文件数 > 512 → 高文件数 btree 元数据开销大 → 后过滤
1. 每谓词独立计数（count-only，廉价）
   定位键范围 + 累加页行数，不物化行地址，触顶即止
   只统计「标量∩向量都覆盖」的存活文件
2. 组合估算（路由依据）
   AND: 估算 = min(各谓词计数)    ← 交集 ≤ 任一（上界安全）
   OR:  估算 = min(累加和, 忽略阈值+1)  ← 并集 ≤ 和
   ※ 必须覆盖全部可下推谓词；存在无索引谓词 → 「计数不可信」档
3. 按候选行数 N 路由
```

#### 「只计数不物化、触顶截断」模式详解（步骤 1 核心）

这个模式解决的核心矛盾是：**路由判定只要一个"数量"做分档，却被迫付"全量枚举"的代价。** 若用普通枚举求 N——遍历 BTree 叶子页、把匹配行地址一个个捞出来——宽过滤（99% 匹配、百万行）下要捞 100 万个地址才知道"该回退现状"，白干一场。三个字逐项拆解：

| 字 | 含义 | 具体省了什么 |
|---|---|---|
| **只计数** | 不产出行地址，只累加页内行数计数器 | 不构造 `Vec<RowAddress>`、不分配/拷贝行地址；BTree 叶子页本有页内行数元信息，count-only 只读页头累加 |
| **不物化** | 跳过"行地址→可传递数据结构"的物化段 | 现状 `metadata.rs:683-744` 是搜索返回 RowAddress → `FileBatchReader` 物化成 Arrow RecordBatch，行号"物化即丢"；count-only 跳过这一整段，只产出一个 `usize` |
| **触顶截断** | 数到「忽略阈值 + 1」即停遍历 | 路由只需判档（≤精确/≤忽略/>忽略），数到忽略阈值+1 结论已定（"超忽略、走现状"），再多数无用。让宽过滤计数成本**有上界** |

**双重截断**（防 BTree 范围查询扫太多页）：既限"数到多少行停"（按忽略阈值），也限"扫多少页停"（按计数页数上界）。呼应 §1.3「DEEP 1024 文件 btree 976ms vs 全扫 261ms」反例。两上界任一触顶即停。

**代价与产出对比**：

| | 普通枚举 | count-only + 触顶截断 |
|---|---|---|
| 产出 | `Vec<RowAddress>`（N 个地址） | 一个数字 N_i（或"触顶"） |
| 代价 | 随 N 线性增长（宽过滤=扫遍所有页+捞全地址） | 上界 = 忽略阈值+1 的页数 |
| 宽过滤(99%)场景 | 扫 100 万行地址才知道要回退（白干） | 数到阈值+1 就停，立即判回退 |
| 用途 | 后续枚举/物化 | **只做路由判定** |

**定位**：用最便宜的代价拿到"够做路由判断"的 N，且绝不让宽过滤场景白付全量枚举代价。是"先量后行"——先量规模（count）决定路线，再按需取行（enumerate）；规模判断错了也不亏（触顶截断 + §4.2 运行时护栏兜底）。**只有精确、受限两档才真正枚举匹配行（这时才付物化代价）；现状档从不枚举，count 已触顶截断，枚举成本为零。**

### 四档路由表

| 档 | 判定 | 是否枚举 | 执行形态 | 召回语义 |
|---|---|---|---|---|
| **小** | N ≤ 精确阈值 | 是（N 行） | 候选行全量精确距离，全局 Top-K | **精确** |
| **中** | 精确阈值 < N ≤ 忽略阈值 | 是（建候选集） | IVF 探测若干簇，簇内逐向量按候选集过滤 | **近似** |
| **大** | N > 忽略阈值（触顶） | **否**（只付估算） | 忽略候选集，纯检索 + 事后过滤 | **近似** |
| **计数不可信** | 存在无索引谓词 | 按正确路径兜底 | 全扫正确基线（召回100%）或显式近似 | 精确/近似（标注） |

### 两个微妙设计点

**① 有界精确化**（仅多谓词 AND，估算 > 精确阈值时）：枚举**计数最小的那个索引**的候选行（上限=忽略阈值+1），对每行在其他索引位图做成员判定 → 精确组合 N（交集语义）。该枚举结果即候选集，精确/受限路径直接复用，无重复工作。OR 不做精确化（并集需枚举全部索引再去重，成本无界）。

**② 现状档运行时护栏**（防「高选择率被误判为宽」）：post-filter 阶段统计返回候选集内实际匹配数，若**不足 K** → 触发**一次** count-first 二次重路由：N ≤ 精确阈值 ⇒ 走精确返回正确结果；N 仍大 ⇒ 保留 post-filter 结果并 EXPLAIN 标注「估算误判，已重路由，确认为宽」。

> **不做**「post-filter 匹配=0 ⇒ 直接返回空」的短路——post-filter 只统计 fetchK 内匹配，0 匹配不代表候选集为空（匹配行可能全落在 fetchK 之外），空集判定只能来自 count（N=0）。

### 阈值：原理、默认值与演进线

**原理**（不任意）：阈值是 **exact 路径成本（随 N 近似线性）与 ANN 路径成本（对 N 不敏感、近乎水平）两条曲线的交点**。

```
精确路径成本 = N × (读一个向量 + 算一次L2距离)
ANN 路径成本 ≈ 纯 IVF 延迟（对 N 不敏感）

精确阈值 = 纯 IVF 延迟 / 单行(读向量+距离)耗时    ← 标定公式
忽略阈值 ≈ 精确阈值 × 10                          ← 启发式倍数
```

**默认值**（保守偏低，安全偏向）：
- SIFT（128维）：精确 ≈ 10,000 行，忽略 ≈ 100,000 行
- GIST（960维）：精确 ≈ 2,000 行，忽略 ≈ 20,000 行

**关键性质——阈值不需精确即可成立**：估算只高估从不低估（AND 取 min、OR 累加均为上界）。故：
- 估算 ≤ 精确阈值 → 走精确：**安全**（实际 ≤ 估算 ≤ 阈值，精确路径不会爆）
- 估算 > 忽略阈值 → 走 post-filter：可能误判 → **运行时护栏兜底**

唯一危险失败模式（低估 N → 爆精确路径）在结构上不可能发生。"高估"由护栏覆盖。**阈值精确值只影响性能，不影响正确性。**

**演进线**（文档已铺，分三层）：
1. Phase 1/2：固定阈值（保守占位）+ 护栏兜底，参数化按表可配；
2. per-table 粗标定：每表测 4 个点（N=1K/5K/10K/50K）锚定交点量级（与 nprobe 标定方式同），**承认无通用阈值**；
3. Phase 3 终态（§6 已写明）：**统计驱动 planner**——BTree 层直方图/zone map 做选择性估算，阈值自适应（AnalyticDB 四路径简化版），用 CBO 取代固定阈值。

## 六、三路径执行步骤

### 路径一：精确（小，N ≤ 精确阈值）

```
① 标量·计数（绑存活文件）     → N，判定精确
② 标量·枚举（标量覆盖文件）    → 匹配行集合（N 行）
③ 向量·按行号取向量           → N 个向量
   （Phase 1 用 read_single_file_rows_at 数据面读列；Phase 2 索引直取 fetch_vectors）
④ 精确距离 + 全局排序         → Top-K
⑤ 标量未覆盖文件兜底           → 全扫出的匹配行同样算精确距离，并入全局 top-K
⑥ 输出候选（≤K）+ _distance → 内核精确重排 → FDW recheck + 物化
```
- 向量索引：`fetch_vectors(行号集合)` —— **不走 ANN**
- Fetch-K：**不放大**

### 路径二：受限（中）

```
① 标量·计数       → N，判定受限
② 标量·枚举       → 候选集（每文件位图，仅「标量∩向量都覆盖」文件）
③ 向量·搜索（全局单索引，内循环逐行过滤）：
   - 标量∩向量都覆盖文件 → 先判候选位图成员，命中才算距离入堆
   - 仅向量覆盖文件      → 不过滤，返回供事后 recheck
④ 兜底合并（向量未覆盖文件全扫并入）
⑤ 全局 top（fetch_k 候选）→ 内核精确重排 Top-K
⑥ FDW recheck + 物化
⑦ 自适应：候选堆不足 K 时扩大 nprobe 重试
```
- 向量索引：`search(查询向量, k, fetch_k, 度量, nprobe, 候选集, 文件覆盖掩码)`
- Fetch-K：现状放大

### 路径三：现状（大，后过滤）

```
① 判定：文件级预判 或 标量·计数触顶 → 宽
② 不枚举标量匹配行（枚举成本为零）
③ 向量·搜索（不受限） → 纯 ANN，无候选集
④ 标量过滤：文件级裁剪 + 本地 recheck（post-filter）
⑤ 兜底合并（向量未覆盖文件全扫）→ 内核精确重排 → 物化
```
- 标量索引：`count(...)` —— 仅此一次，不枚举
- Fetch-K：现状放大

### 自适应探测簇数（受限路径，§4.3）

- **触发**：候选堆大小 < K（不是 < FetchK）。
- **算法**：初始 nprobe = `10 × sqrt(N/总量)`；不足 K 时翻倍，最多重试 3 次；仍不足则以已收集结果返回。
- **不重复计算**：已探测簇结果保留在堆中，重试只追加新簇。
- **nprobe 现状与改造**：引擎侧 `search` 从 `parameters` 读 nprobe（per-search 可传），但 FDW 现作**表级 option**透传（`ALTER FOREIGN TABLE ... OPTIONS (ADD nprobe 'N')`）。自适应重试需在 search 内编排——需将 nprobe 提升为 per-search 参数，或引擎内临时覆盖首轮值再重试。

## 七、多谓词与索引覆盖（正确性关键）

### 组合候选集

把「组合」拆两阶段，互不混同：
- **组合估算**（路由用，count-only）：每谓词独立计数，AND 取 min / OR 累加。估算 ≤ 精确阈值 ⇒ 精确档免费判定；估算触顶 ⇒ 大档不枚举。
- **组合枚举**（执行用，小/中两档）：各索引候选集 AND 求交 / OR 求并 → 精确候选集，精确/受限路径直接复用。

**为什么必须**：路由依据必须是覆盖**全部可下推谓词**的估算或精确化组合计数。单索引超集估算会把高选择率永远挡在精确路径外（已禁止）；「存在无索引谓词」时连可信估算都凑不齐，走「计数不可信」档。

### 索引覆盖组合（§5.2）

| 文件覆盖组合 | 行级预过滤 | 搜索内循环过滤行为 |
|---|---|---|
| 标量 ∩ 向量都覆盖 | 生效 | 逐行查候选位图，命中才算距离入堆 |
| 仅向量覆盖（标量未覆盖） | 不生效 | 不过滤，候选全部返回 + 事后 recheck |
| 仅标量覆盖 / 都未覆盖 | 不生效（向量侧） | 向量索引内无该文件行，全扫兜底 |

- 受限搜索在**全局索引内循环逐行过滤**（非 per-file 分区执行）。
- 候选位图按全局 `(file_path/file_index, row_position)` 组织，按文件分组存储供内循环 O(1) 判定。
- **精确路径例外**：候选行在「标量覆盖」文件内枚举，向量按行号取；精确路径不依赖向量索引覆盖，故「仅标量覆盖」文件也能精确处理。

### 精确路径成本护栏（覆盖占比）

「仅标量覆盖（向量未覆盖）」文件在精确路径下按全扫读列处理。占比过高致总延迟超预算（**预算 = 纯 IVF 延迟 × 精确预算系数**，默认 1.0）则**转受限**（整体降为近似语义；受限下「仅标量覆盖」文件仍全扫精确并入，无漏行）。

- 口径（数据量占比）：`未覆盖容忍占比 ≈ 预算 / 全扫总延迟`，默认 SIFT 9% / GIST 8%。
- 覆盖完整时护栏不触发，「高选择率精确 = 100% 召回」保证成立。
- 实现基础：向量覆盖文件集直接取现成 `live_covered_data_files`，基于全局 `file_ids`/`file_indices` 判定，非 per-file 子索引。

## 八、查询形态边界（§5.3）

| 形态 | 示例 | 支持 | 处理 |
|---|---|---|---|
| 向量 top-K ∧ 标量 AND | 主场景 | ✅ | 核心路径 |
| 标量 AND 多列 | `a=1 AND b=2 AND vec~q` | ✅ | 组合候选集求交 + recheck |
| 标量 OR（同列等值） | `cat IN ('a','b')` | ✅（部分） | 候选集并集 |
| 标量 OR（跨列） | `a=1 OR b>5` | ⚠️ | 显式回退全扫 + recheck，EXPLAIN 标注 |
| 标量 NOT | `NOT (cat='x')` | ⚠️ | 补集对 ANN 无帮助，回退全扫 |
| **向量参与的 OR** | `cat='x' OR vec~q` | ❌ | 结果集非 top-K 形状，列为非目标 |

**原则**：只加速「向量 top-K ∩ 标量 AND」。不支持的形态**显式回退并告警**，正确性（recheck 兜底）优先于性能。回退路径加运行时成本护栏（行数/时间上限），避免误写查询并发下打爆 IO。

## 九、正确性与并发

### 正确性（四道防线）

| 层 | 机制 | 保证 |
|---|---|---|
| 索引检索 | 候选集过滤 / 精确距离 | 返回行必满足标量条件（**无假阳性**） |
| 覆盖兜底 | 未覆盖文件全扫并入 | **无漏行**（部分覆盖安全） |
| 本地 recheck | FDW 保留原始谓词 | 最终语义正确性最后防线 |
| 内核重排 | 精确距离 + 全局 Top-K | 排序正确 |

### 并发（§7.2）

- **无共享可变状态**：候选集查询私有；索引 segment 只读共享。
- 计数/枚举为只读索引操作，多查询并发安全。
- 自适应 nprobe 只改当前查询检索参数。
- 沿用混合任务组分区分桶（`scan.rs:125-140`、`iceberg_fdw.cpp:1393`），DOP 复用现有机制。

## 十、实现路线（§6，先正确性后优化）

> 文档第 1–5、7 节是**一份完整的目标设计**。Phase 只是落地次序，不是设计变体。

### Phase 1 —— 正确性基线

目标：功能全可用——高选择率精确（召回100%）、中/低选择率不劣化；性能先保证「不劣化」，优化后置。

**接口新建清单**（均从 0 新建）：`VectorSearchRequest` 增候选集+文件覆盖掩码并改写 IVFPQ 内循环；`VectorIndex` 新建 `fetch_vectors`；`ScalarIndex` 新建 count-only；search 内编排自适应 nprobe。

- 标量计数查询（count-only，新建）：按 `file_index` 绑定存活文件。
- 组合估算 + 有界精确化。
- 标量枚举 + 组合候选集。
- **精确路径**：Phase 1 用 `read_single_file_rows_at` 数据面读列实现；Phase 2 `fetch_vectors` 索引直取。
- 受限路径：内循环逐行按候选集+文件覆盖掩码过滤；adaptive nprobes 基础版。
- 桥接：混合检索配置从「二选一」扩为「向量+可选标量预过滤」，一次调用。
- FDW：规划期识别、匹配索引（复用多候选择优）、组装配置、EXPLAIN 展示路由档+回退原因、回退保护。

### Phase 2 —— 优化与扩展

- `fetch_vectors` 高效化（数据面读列 → 索引直取）；自适应 nprobe 调优；路由阈值标定脚本（per-table 粗标定）。
- 跨列 OR 并集；无索引谓词覆盖索引自动建议。
- 覆盖组合处理成本优化；并发稳定性专项；性能目标收紧。

### Phase 3（远期）

- **融合索引**（方案1）：向量索引构建时携带标量列，服务高基数宽过滤。仅当 Phase1/2 宽过滤回退成为实测瓶颈后启动。
- **PQ 码级过滤**：码块附过滤位向量，判断从逐条到逐块。
- **统计驱动 planner**：BTree 直方图/zone map 自适应阈值——**阈值路由的终态**，用 CBO 取代固定阈值。

## 十一、最终形态（演进终点全景）

Phase 1→2→3 不是三个独立方案，而是**朝同一终态架构收敛的落地次序**。本节把演进终点集中说清，避免把过渡形态误当终态。

### 11.1 路由决策的终态：从「固定阈值切档」到「CBO 比成本」

| 维度 | Phase 1/2（过渡） | Phase 3 终态 |
|---|---|---|
| 路由依据 | 估算 N vs **固定阈值**（常数） | 估算两条路径**各自成本**，取 min |
| 阈值 | 写死的精确/忽略阈值，per-table 标定 | **无固定阈值**，查询时按统计实时算 |
| 选择性来源 | count-only 计数拿 N | BTree 直方图/zone map 估算 σ，无需全量 count |
| 成本系数 | 隐含在阈值里 | 显式成本模型（单行读取代价、ADC 代价等），可标定 |
| 自适应粒度 | per-table 参数 | per-query 实时 |

**关键澄清**：CBO 也是"带噪估算"，不是变精确。它的进步是**更自适应**（不同表/查询自动算），不是"变准"。真正让设计成立的不是"预判变准"，而是**两段式决策（预判 + 运行时护栏纠正）让预判错得起**——见 11.2。

### 11.2 终态的可靠性根基：两段式决策 + 运行时护栏

这才是整套路由能成立的根本，无论 Phase 几都不变：

```
预判（规划期，廉价估算）     →  选一条路走
  │
  ▼
执行中/后观察真实结果         →  发现错了就切
  ├─ post-filter 实际匹配不足 K  →  count-first 重路由回精确（§4.2 护栏）
  ├─ 候选堆不足 K              →  扩大 nprobe 重试（§4.3）
  └─ 精确路径超预算             →  覆盖占比护栏转受限（§4.1）
```

固定阈值/CBO/统计驱动都只是**预判层的演进**，让预判尽量准；但预判永远带噪。护栏是**纠正层**，让预判不准也兜得住。**预判准不准只影响性能，护栏保正确性。** 这是设计的可靠性根基，Phase 1→3 不变。

### 11.3 过滤-向量负相关的终态解法：融合索引 + 属性分层聚类

这是 §十三 标注的首期盲区，终态由两件事补：

- **融合索引**（方案1）：向量索引构建时携带标量属性列，宽过滤内联过滤。
- **属性分层聚类**（调研报告 §9.4 P3）：把高频过滤属性纳入簇分配维度，使簇内过滤-向量**正相关**——对应 Google 综述"正相关减少搜索代价"结论。

补法前置条件：先用"q 与过滤属性分布的相关性"做在线探测，**负相关明显时强制走 bitmap 下推**而非无过滤+后过滤（调研报告 §9.4 建议）。

### 11.4 三档框架在终态是否保留

**保留**。统计驱动 planner 不消灭三档，而是**让档位边界动态化**：
- AnalyticDB 四路径（暴力/位图下推/谓词下推/后过滤）就是动态化的多档，按 CBO 在四路径间选；
- 本方案三档（精确/受限/现状）与之同构，终态是"三档仍在，但由 CBO 而非固定阈值选档"。
- 三档对应的三种执行机制（精确暴力 / 位图下推 IVFPQ 内循环 / post-filter）是业界共识，不会过时。

### 11.5 终态触发条件（不盲目演进）

Phase 3 的三个演进项均有**实测门槛**，非默认推进：

| 终态项 | 触发条件 | 触发前行为 |
|---|---|---|
| 统计驱动 planner | 固定阈值成为性能瓶颈 | per-table 标定 + 护栏兜底 |
| 融合索引 | Phase1/2 宽过滤回退现状成为实测瓶颈 | 接受宽过滤走现状 |
| PQ 码级过滤 | 受限路径逐行位图判断成本成为瓶颈 | 逐条判断（可接受） |

**原则**：不过度演进。每档终态由实测瓶颈驱动，而非"技术先进性"驱动。

### 11.6 一句话终态

**三档执行机制（精确/位图下推/post-filter）不变，路由决策从固定阈值演进到 CBO 实时比成本，过滤-向量负相关盲区由融合索引+属性分层聚类补；全程靠两段式决策 + 运行时护栏让预判错得起——预判准不准只影响性能，护栏保正确性。**

## 十二、验收口径（需求 §3.3/§3.4，与实现阶段绑定）

性能对比分两层基线：
- **正确基线**：全扫 + recheck（现状拿正确结果只能全扫），SIFT 2358ms / GIST 18883ms
- **近似基线**：纯 IVF post-filter（现状实际行为，结果不保证正确）

| 档 | 召回目标 | 相对全扫（必赢） | 相对纯 IVF |
|---|---|---|---|
| 高 1% | 100%（精确） | ≥20× | ≤1.0× 目标 / ≤0.5× 惊喜 |
| 中 5% | ≥ IVF post-filter 召回 | ≥5× | 保底 ≤1.5× |
| 宽 99% | = 纯 IVF 召回 | ≥10× | ±10% 不劣化 |

**与实现阶段绑定**（避免 Phase 1 验收误判）：
- 精确路径 Phase 1 用数据面**顺序读列**，相对纯 IVF 目标暂放宽至 **≤1.5×**（以正确性为先）。
- Phase 2 `fetch_vectors` 高效化（索引直取）后收紧至 **≤1.0×**。

真正价值在相对正确基线：混合查询 QPS 是全扫的 10–100 倍。

## 十三、已知局限（设计诚实标注）

1. **选择性单维路由的盲区：过滤-向量负相关**。调研报告 §9.4 明列其为"召回杀手"。首期用 recheck 保正确性、用 P3 融合索引/属性分层聚类补性能，接受此盲区。
2. **路由判定本身的成本**。宽过滤下 count-only 虽触顶即止仍可能扫大量叶子页（DEEP 1024 文件 btree 976ms vs 全扫 261ms 即反例）。§4.1 步骤0「存活占比>90% 直接回退」兜底，但高基数+范围查询的计数成本需标定实测。
3. **固定阈值非终态**。不同表维度/行数/向量大小/列存布局/硬件不同，无通用阈值（FANNS 基准结论）。Phase 1/2 靠上界估算+护栏结构性安全兜底，Phase 3 统计驱动 planner 取代。
