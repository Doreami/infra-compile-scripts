## 1. 概述

### 1.1 目标

为「相似度 + 标量约束」的组合查询提供索引加速：

```sql
SELECT id FROM tab
WHERE category = 'electronics'
ORDER BY vec <-> '<query_vector>'::vector
LIMIT 10;
```

把标量条件从「向量检索后的事后过滤（post-filter）」前移为「向量检索内的预过滤」，按标量过滤**选择率**自动在三种执行形态间路由：高选择率**精确**、中等**近似加速**、低选择率**不劣化**。复用现有标量/向量索引，**不改变索引存储格式**。

### 1.2 非目标

- 向量排序（`ORDER BY vec` 无相似度）加速。
- 融合索引（向量索引存储中携带标量列）——列为远期演进。
- 规划器成本估算 / 统计信息收集——列为远期。
- **多查询向量批量检索（`IN` 子句 / 子查询）加速**——首期仅支持单向量 Top-K。
- **向量参与的 OR**（`cat='x' OR vec~q`）——结果集非 top-K 形状，ANN 无法直接加速，列为非目标（显式回退，见 §5.3）。

### 1.3 现状基线（实现前）

| 环节 | 现状 |
|---|---|
| 路由 | 向量 top-K 与标量索引路径**互斥**；含标量的混合查询只走向量路径 |
| 标量过滤 | 文件级谓词下推 + FDW 本地 recheck（post-filter），不进向量检索 |
| 召回兜底 | 内核 `FetchK = TopK × 5`（夹 [50, 10000]），高选择率下无保证 |
| 物化 | 候选行全量物化（Parquet 读 + Arrow 解码），物化是最大耗时 |

实测基线（同环境 A/B 参考，`ORDER BY vec <-> q LIMIT K`，DOP=1/DOP=8）：

| 数据集 | 规模/维度 | IVF K=10 | FullScan K=10 | 官方召回@10 |
|---|---|---|---|---|
| SIFT | 100万 / 128 | 212ms / 63ms | 2358ms | 90.6% |
| GIST | 100万 / 960 | 1467ms / 311ms | 18883ms | 78.4% |

标量侧基线（`WHERE id = X` 点查）：SIFT/GIST btree 24–29ms（32 文件）；**高文件数下 btree 有随文件数的元数据解析开销，可能反超全扫**（DEEP 1024 文件：btree 976ms vs 全扫 261ms）。

## 2. 总体架构

### 2.1 两级裁剪

```
查询
  │
  ▼
① 文件级裁剪（第零级，现状保留）   Iceberg 文件级谓词 → 排除不可能匹配标量的数据文件
  │                                 （对向量检索与兜底扫描两条路径都生效）
  ▼
② 行级预过滤（本次新增）           标量 BTree 计数/枚举 → 候选行集合 → 向量检索只在该集合内出候选
  │
  ▼
③ 物化                          只剩命中标量的候选行 → 直击「物化是最大耗时」瓶颈
```

### 2.2 组件分工

| 层 | 职责 | 改动 |
|---|---|---|
| **内核** | 识别 `ORDER BY vec <-> q LIMIT K`，产出 Top-K/FetchK，精确重排 | 无改动 |
| **FDW** | 规划期识别混合查询、匹配标量/向量索引、组装混合检索配置；执行期一次调用 | 规划/路由 |
| **桥接** | 混合检索配置解析；从「向量/标量二选一」扩为「向量 + 可选标量预过滤」 | profile 扩展 |
| **索引引擎** | 编排一次检索：标量计数 → 路由 → 枚举/向量检索 → 兜底合并 | 检索编排 + 内层过滤 |

### 2.3 业界对齐（依据调研报告）

本方案的「标量索引 → 候选集（位图）→ 下推向量检索」与业界主流做法一致，且**选择性自适应路由**是所有成熟系统（AnalyticDB CBO 四路径、Milvus 代价式、Qdrant 基数规则、Weaviate 15% 阈值、LanceDB adaptive nprobes）的共识：

| 本方案 | 业界对应 |
|---|---|
| 标量 BTree 计数/枚举 → 候选行集合 | FAISS `IDSelectorBitmap` / Lance `RowAddrMask` / Milvus bitset（属性索引先过滤，位图传进向量搜索） |
| 中等选择率：位图下推 IVFPQ 内层过滤 | FIVF-PQ / Rii「按选择性在预过滤与融合过滤间自适应切换」；Lance「bitmap 下推 IVF 分区内搜索」 |
| 高选择率：候选集小 → 精确暴力 | Weaviate `flat-search cutoff`（<15% 命中转暴力）、Doris 强过滤回退暴力 |
| 低选择率：回退现状 post-filter | AnalyticDB CBO「几乎无过滤效果 → 先 HNSW 再过滤」 |
| 受限路径自适应放大探测簇数 | Lance `adaptive nprobes`（不足 K 时扩大探测分区，`maximum_nprobes` 封顶） |
| 文件级裁剪为第零级（现状 Iceberg 文件级谓词） | Lance「Parquet footer IVF + 文件剪枝栈」（湖仓文件级预过滤） |

> **与 Lance 的差异**：Lance 的 footer IVF 是**按文件**组织索引分区（文件剪枝栈可直接裁剪）；本方案向量索引为**全局单索引**（分区跨文件、行记 `file_index`），文件级裁剪走 Iceberg 文件级谓词（第零级），行级过滤在全局搜索内循环内逐行完成（§5.2）。业界对齐落在「湖仓文件级预过滤」的理念层，机制按本方案全局索引实现。

关键结论（调研报告三重验证）：**不存在全局最优方案，最优选择由过滤选择性、过滤-向量相关性、K、数据分布共同决定**——所有成熟系统都在做查询期自适应，本方案的三级路由正是这一共识的落地。

## 3. 请求与数据流

### 3.1 混合检索请求结构

在现有「向量检索配置」基础上**新增可选字段**，不破坏既有请求：

```
混合检索配置
├─ 向量侧（必填，沿用现状）
│   ├─ 向量索引名
│   ├─ 查询向量 / 距离度量 / Top-K / Fetch-K
│   └─ 检索参数（探测簇数 nprobe 等）
├─ 标量侧（可选，新增）
│   ├─ 标量索引名列表（每个可下推谓词对应的索引，用于组合候选集）
│   ├─ 标量表达式（列 / 算子 / 值）
│   └─ 存活文件列表（文件级裁剪结果，作为计数/枚举上下文）
└─ 路由控制（可选）
    └─ 路由阈值（精确阈值 / 忽略阈值，参数化）
```

标量侧缺省 = 现状纯向量检索（向后兼容）。标量表达式同时进入两处：文件级谓词下推 + 行级预过滤。

> **「新增」= 引擎能力从 0 新建**（非扩展现有字段，代码现状已核实）：① **候选集下推**——`VectorSearchRequest` 现无 selector/bitmap 字段（runtime.rs），需新增候选集 + 文件覆盖掩码入参，并改写 IVFPQ 扫描内循环（ivf_pq.rs）；② **按行号取向量**——`VectorIndex` trait 现仅 `search` 一个方法，需新建 `fetch_vectors`；③ **标量 count-only**——`ScalarIndex::search` 现只返回 RowAddress 再物化，需新建「只计数不物化、触顶截断」模式；④ **自适应 nprobe**——现单趟解析 nprobe 无重试，需在 search 内编排（见 §4.3）。落地工作量集中在索引引擎层，见 §6 实现路线。

### 3.2 执行时序

```
规划期（FDW）
  ① 识别混合查询：向量 top-K 与可下推标量谓词同时存在
  ② 匹配标量/向量索引（一次索引发现返回全量；多标量索引用多候选择优）
  ③ 标量谓词分流：
       - 进文件级谓词（Iceberg 谓词裁剪）
       - 进行级预过滤表达式（覆盖索引键列的谓词）
  ④ 组装混合检索配置，序列化进执行计划（EXPLAIN 显示：向量索引 + 标量预过滤索引 + 路由档 + 回退原因）

执行期（FDW → 桥接 → 引擎，一次调用）
  ⑤ 引擎内：
       a. 文件级预判 + 每谓词 count-only 计数 → 组合估算 → 路由（多谓词 AND 歧义带有界精确化；OR 估算路由；现状档运行时护栏）
       b. 按路由枚举匹配行 / 构建候选集
       c. 向量检索（精确 / 受限 / 忽略）
       d. 未覆盖文件兜底合并（覆盖段走索引、未覆盖段走全扫，并入同一结果流）
       e. 返回候选行（含 _distance 列）
  ⑥ 内核：精确距离 + 全局 Top-K 重排
  ⑦ FDW：本地 recheck（标量谓词兜底）+ 物化
```

> **并行（DOP）**：混合检索沿用混合任务组的分区分桶。**计数/路由为查询级决策（全局一次）**，各任务组对各自文件按同一路由执行；候选集为只读共享（每文件位图），组间无冲突。多连接并发同样支持（每查询独立）。

### 3.3 候选行集合的表示

标量枚举返回「数据文件路径 + 行号」集合（精确，与 Iceberg position deletes 同键空间，可复用删除掩码）。表示分档：

| 候选集规模 | 表示 | 成员判断成本 |
|---|---|---|
| 小 | 行号数组 | 线性/二分 |
| 中 | 每文件行号位图（Roaring 风格） | 常数时间 |
| 大 | 不建集合（走现状路径） | — |

## 4. 三级路由设计

### 4.1 判定机制（如何路由）

**路由判定用「组合估算」，不用「组合枚举」**——判定前先枚举，判「宽」就得白跑完整标量检索，与「回退后过滤」自相矛盾。**估算只允许做上界**：宁可把「可能小」判成小，不把「其实小」判成大（大档另有运行时护栏兜底，见步骤 3）。

判定由廉价到昂贵递进，每层可触顶截断：

0. **文件级预判（免费）**：文件级裁剪后看存活文件占比。
   - 存活文件占比 > 90% ⇒ 过滤几乎不裁剪 ⇒ 直接走后过滤（现状），连索引都不碰；
   - 存活文件数 > 文件数阈值（如 512）⇒ 高文件数下 BTree 元数据解析开销大 ⇒ 直接走后过滤。
1. **每谓词独立计数（廉价，count-only）**：对每个可下推谓词在对应标量索引上做**计数查询**——定位键范围 + 累加范围内页的行数，**不物化行地址、不返回行号**；只统计存活文件内、且「标量 ∩ 向量都覆盖」文件的匹配行；计数页数超上界或计数到「忽略阈值 + 1」即停。**实现**：标量 BTree 为全局索引；count 模式规划的紧凑键为 `(file_index << 32) | row_pos`（**现状**标量行地址为 `RowAddress{file_path, row_position}` 字符串路径，count 模式新建时再紧凑化），存活文件过滤即按 `file_index` 判定，属**新建 count 模式**（现 `ScalarIndex::search` 只返回 RowAddress，无只计数不物化）。
2. **组合估算（路由依据）**：按谓词逻辑组合各谓词计数，得到候选行数**上界**：
   - **AND**：`估算 = min(各谓词计数)`（交集 ≤ 任一）；
   - **OR**：`估算 = min(累加和, 忽略阈值 + 1)`（并集 ≤ 和）。
   - **估算可信性（关键）**：估算必须覆盖**全部可下推谓词**。**存在无索引谓词、只能用单索引超集估算时，禁止用该估算做路由**——超集会严重高估 N，把高选择率误判为「大」，精确路径永远无法触发（见「计数不可信」档）。
   - **有界精确化（仅多谓词 AND 且估算 > 精确阈值）**：估算对上界安全，但对「中/大」边界不可信（谓词相关时交集可能远小于估算）。为区分中/大：枚举**计数最小的那个索引**的候选行（上限 = 忽略阈值 + 1），对每行在其他索引位图上做成员判定 → 精确组合 N（**交集语义**）。该枚举结果即候选集，精确/受限路径直接复用，无重复工作；成本有界：≤ min(各计数, 忽略阈值+1) 行成员判定，绝不全表。
   - **OR 不做有界精确化**：并集计数需枚举**全部**索引再去重，成本无界。OR 保持纯估算路由——估算 ≤ 精确阈值 ⇒ 精确（并集 ≤ 和，安全上界）；估算 ≤ 忽略阈值 ⇒ 受限（并集 ≤ 和 ≤ 忽略阈值，**确非宽**）；估算触顶 ⇒ 现状（不枚举，由现状档运行时护栏兜底「其实小」的反例）。小并集 OR 可能保守走受限而非精确，属可接受的方向性保守。
3. **按候选行数 N 路由**（N = 估算或精确化后的匹配行数）：

| 档 | 判定 | 是否枚举 | 执行形态 | 召回语义 |
|---|---|---|---|---|
| **小** | N ≤ 精确阈值 | 是（N 行） | 对候选行**全量精确距离**，全局 Top-K | **精确** |
| **中** | 精确阈值 < N ≤ 忽略阈值 | 是（N 行，建候选集） | IVF 探测若干簇，簇内逐向量按候选集过滤 | **近似** |
| **大** | N > 忽略阈值（触顶/超页） | **否**（只付估算） | 忽略候选集，纯检索 + 事后过滤 | **近似** |
| **计数不可信** | 存在无索引谓词 | 按正确路径兜底 | 全扫正确基线（保证召回 100%）或显式近似（ANN + recheck，标注） | 精确 / 近似（标注） |

- **只有小/中两档才枚举**匹配行；**大档只付估算成本**（每谓词键范围页扫描，不物化行），枚举成本为零。
- **单谓词 / 覆盖复合索引**：估算即精确计数，无需精确化；宽过滤直接判「大」→ 现状，零枚举。
- **多谓词且估算触顶（> 忽略阈值）**：默认判「大」→ 现状（不枚举）。估算为上界，「其实高选择率」的反例（各谓词都宽、交集极小）由**现状档运行时护栏**兜底（§4.2 路径三）：post-filter 后实际匹配不足 K 时，count-first 二次重路由。边界细化（估算略超忽略阈值时的有界精确化确认中/大）为实现期可选优化（Phase 2 评估），**仅 AND**。
- **精确路径成本护栏（覆盖占比）**：「仅标量覆盖（向量未覆盖）」文件在精确路径下按全扫读列处理（§4.2 路径一 / §5.2）。若这些文件占存活数据比例过高，精确路径总延迟超出预算（**预算 = 纯 IVF 延迟 × 精确预算系数**，默认系数 1.0），则**转受限**（整体为近似语义；受限下「仅标量覆盖」文件仍全扫精确并入，无漏行）。
  - **口径（数据量占比，非文件数）**：`未覆盖容忍占比 ≈ 预算 / 全扫总延迟`，其中「全扫总延迟」= 当前存活数据全扫延迟（SIFT 2358ms / GIST 18883ms），**假设文件大小近似均匀**；文件大小不均匀时，精确路径在「仅标量覆盖」文件上的全扫成本按**数据量加权**估算（Σ 未覆盖文件数据量 × 单行全扫成本），或取**最坏单文件全扫延迟**做保守担保。「全扫总延迟」可由 Iceberg 文件元数据（各文件数据量/行数）累加估算，无需实测全扫。
  - 默认值（基于全扫总延迟口径）：SIFT `212/2358 ≈ 9%`、GIST `1467/18883 ≈ 8%`。固定 10% 只是 SIFT 口径的保守取整；GIST 单文件全扫成本高 8×，同预算下容忍占比更低。阈值参数化 + 标定脚本（见 §6）以实测数据量分布校准。
  - **实现基础**：「仅标量覆盖（向量未覆盖）」文件集 = 标量索引覆盖文件 ∖ 向量索引覆盖文件；向量覆盖文件集直接取现成的 `live_covered_data_files`，基于全局 `file_ids`/`file_indices` 判定，非 per-file 子索引。
  - **覆盖完整**（标量∩向量覆盖 = 全量存活文件）时该护栏不触发，「高选择率精确 = 100% 召回」保证成立；覆盖不足时召回口径降为「≥ 现状 post-filter」（需求 §八）。
- 「精确阈值」= 精确距离成本可接受的候选行数上限（与距离单位成本共同决定）；「忽略阈值」= 过滤几乎不裁剪的比例，预过滤无收益即回退。
- **默认阈值（首版，待标定）**：按数据集维度给出，避免 SIFT/GIST 距离成本差 7.5× 导致同一阈值在 GIST 上超时：
  - SIFT（128 维）：精确阈值 ≈ 10,000 行，忽略阈值 ≈ 100,000 行；
  - GIST（960 维）：精确阈值 ≈ 2,000 行，忽略阈值 ≈ 20,000 行；
  - 标定公式：`精确阈值 ≈ 纯 IVF 单查询延迟 / 单行向量读取+距离耗时`，`忽略阈值 ≈ 精确阈值 × 10`。
- 计数与枚举均**绑定存活文件列表**（文件级裁剪结果），避免分区裁剪后计数失真。
- 阈值参数化 + 标定脚本（随实现路线产出，见 §6），默认保守（宁走受限，不因误判精确而回退超时）。

### 4.2 三路径执行步骤与索引参数

三类索引调用（贯穿下述路径；N 为存活文件内匹配行数）：

| 调用 | 请求参数 | 返回 |
|---|---|---|
| 标量·计数（每谓词，count-only） | `{索引名, 表达式, 存活文件, 计数上限}`（上限=忽略阈值+1，触顶即止） | 该谓词匹配行数 N_i（→ 组合估算 / 有界精确化） |
| 标量·枚举 | `{索引名, 表达式, 存活文件, 行数上限}`（上限=忽略阈值） | 匹配行集合（文件+行号，精确；多谓词取交并组合） |
| 向量·搜索 | `{索引名, 查询向量, k, fetch_k, 度量, nprobe, 候选集?}` | 候选行（含 _distance） |
| 向量·按行号取向量 | `{索引名, 行号集合}` | 对应向量（供精确距离）——新建能力；Phase 1 以数据面 `read_single_file_rows_at` 实现，Phase 2 索引直取 |

> 三路径均按**文件覆盖组合**分组（见 §5.2）执行行级过滤策略：候选集/受限搜索只作用于「标量 ∩ 向量都覆盖」的文件，其余文件按各自形态兜底，保证**无漏行**。向量索引为**全局单索引**（分区跨文件、行记 `file_index`），过滤发生在搜索**内循环逐行**处，非 per-file 分区执行。

**路径一：精确（小，N ≤ 精确阈值）**

```
① 标量·计数（绑存活文件）     → N，判定精确
② 标量·枚举（标量覆盖文件）    → 匹配行集合（N 行）
③ 向量·按行号取向量           → N 个向量（Phase 1 用数据面 read_single_file_rows_at 按行号读列；Phase 2 索引直取 fetch_vectors）
④ 精确距离 + 全局排序         → Top-K（对标量覆盖文件的候选行）
⑤ 标量未覆盖文件兜底           → 全扫（文件级标量裁剪）出的匹配行**同样算精确距离**，并入全局 top-K
⑥ 输出候选（≤K）+ _distance → 内核精确重排 → FDW recheck + 物化
```

- 传给**标量索引**：`count(表达式, 存活文件)`、`search(表达式, 存活文件, limit=N)`
- 传给**向量索引**：`fetch_vectors(行号集合)` —— **不走 ANN 搜索**（新建能力，见 §3.1）
- Fetch-K：**不放大**（无需兜召回）

**路径二：受限（中，精确阈值 < N ≤ 忽略阈值）**

```
① 标量·计数       → N，判定受限
② 标量·枚举       → 匹配行集合 → 构建候选集（每文件位图，仅「标量∩向量都覆盖」文件）
③ 向量·搜索（全局单索引，内循环逐行过滤）：
   - 行在「标量∩向量都覆盖」文件 → 先判候选位图成员（(file_index, row_position)），命中才算距离入堆
   - 行在「仅向量覆盖」文件      → 不过滤，返回供事后标量 recheck（该文件退化为现状路径）
④ 兜底合并（向量未覆盖文件全扫并入）
⑤ 全局 top（fetch_k 候选）→ 内核精确重排 Top-K
⑥ FDW recheck + 物化
⑦ 自适应：候选堆不足 K 时扩大 nprobe 重试（见 §4.3）
```

- 传给**标量索引**：`count(表达式, 存活文件)`、`search(表达式, 存活文件)`（全量枚举到忽略阈值）
- 传给**向量索引**：`search(查询向量, k, fetch_k, 度量, nprobe, 候选集, 文件覆盖掩码)` —— **候选集 + 文件覆盖掩码，内循环逐行过滤**（新建入参，见 §3.1）
- Fetch-K：现状放大（兜召回）

**路径三：现状（大，后过滤）**

```
① 判定：文件级预判（存活占比 > 90% / 文件数超阈值）或 标量·计数触顶 → 宽
② 不枚举标量匹配行（枚举成本为零）
③ 向量·搜索（不受限） → 纯 ANN，无候选集（向量覆盖文件）
④ 标量过滤：文件级裁剪（filter_json 进扫描）+ 本地 recheck（执行器 post-filter）
⑤ 兜底合并（向量未覆盖文件全扫）→ 内核精确重排 → 物化
```

- 传给**标量索引**：`count(表达式, 存活文件, cap)` —— **仅此一次，不枚举**
- 传给**向量索引**：`search(查询向量, k, fetch_k, 度量, nprobe)` —— **无候选集参数**
- Fetch-K：现状放大
- **运行时护栏（防「高选择率被误判为宽」）**：估算为上界；多谓词且谓词相关时，真实候选集可能远小于估算。post-filter 阶段统计返回候选集内实际匹配数，若**不足 K**（Top-K 都填不满）⇒ 触发**一次**二次重路由（**count-first**，廉价）：重跑 count-only 确认真实 N——N ≤ 精确阈值 ⇒ 走精确路径返回正确结果；N 仍大（查询确实是宽、只是匹配行未落 fetchK）⇒ 保留当前 post-filter 结果并 EXPLAIN 标注「估算误判，已重路由，确认为宽」；N = 0 ⇒ 短路返回空（与 §7.3 边界一致）。罕见反例的正确性兜底，不进入常规路径。
  - **不做**「post-filter 匹配 = 0 ⇒ 直接返回空」的短路：post-filter 只统计 fetchK 内的匹配，0 匹配**不代表**候选集为空（匹配行可能全部落在 fetchK 之外），直接返回空会造成正确性回退；空集的正确判定只能来自 count（N = 0）。

**参数总览**

| 路径 | 标量索引调用 | 向量索引调用 | 标量过滤位置 | Fetch-K |
|---|---|---|---|---|
| 精确 | count → search（全量枚举） | fetch_vectors（行号） | 枚举集即匹配行 | 不放大 |
| 受限 | count → search（全量枚举） | search + 候选集过滤 | 向量检索内联（成员过滤） | 现状放大 |
| 现状 | count（触顶即止，不枚举） | search（无过滤） | 检索外 recheck（post-filter） | 现状放大 |

### 4.3 自适应探测簇数（受限路径）

- **触发**：候选堆大小 < K（而非 FetchK——FetchK 是缓冲，K 是必须返回数）。
- **算法**：初始 nprobe 用启发值（如 `10 × sqrt(N / 总量)`，N 为匹配行数）；不足 K 时 nprobe 翻倍，最多重试 3 次；仍不足则以已收集结果返回（由内核重排，宁可少返回也不无限放大）。
- **不重复计算**：已探测簇的结果保留在堆中，重试只追加新簇。
- **与现状可比性**：召回验收以「不低于现状 post-filter 召回」为底线（见需求文档 §3.3）。
- **nprobe 现状与改造**：引擎侧 `search` 从 `VectorSearchRequest.parameters` 读 nprobe（per-search 可传），但 FDW 目前把它作为**表级 option**（`ALTER FOREIGN TABLE ... OPTIONS (ADD nprobe 'N')`）透传。自适应重试需在 search 内部编排（当前单趟解析、无重试）——需将 nprobe 提升为 per-search 参数，或由引擎在 search 内临时覆盖首轮值再重试。

## 5. 多标量索引与多谓词（组合候选集）

**范围**：向量侧本次只支持**一个向量索引**（单向量列的 top-K）；标量侧**支持一个或多个标量索引**参与同一查询。

### 5.1 组合候选集（业界标准，也是路由可信性的前提）

业界（Milvus bitset、Lance RowAddrMask、FAISS IDSelector）的做法是：标量引擎对**全部可索引谓词**求值，用交/并组合成**单一候选集（位图）**，再传给向量搜索。本方案把「组合」拆成两个阶段——**路由用估算、执行用枚举**，互不混同：

- **组合估算（路由用，count-only，不枚举行号）**：每个可下推谓词在对应索引上做独立计数，按谓词逻辑组合成候选行数**上界**——**AND 取 min、OR 累加**（§4.1 步骤 2）。估算 ≤ 精确阈值 ⇒ 精确档免费判定（交集 ≤ 任一索引计数）；估算触顶 ⇒ 大档，不枚举。
- **组合枚举（执行用，只在小/中两档或歧义带）**：各可索引谓词的候选集 **AND 求交 / OR 求并** → 组合候选集（对索引覆盖的谓词而言即精确匹配集）。精确/受限路径的枚举结果**直接作为候选集**，无重复工作；多谓词 AND 且估算在歧义带时，先做「有界精确化」得精确 N 再定档；**OR 不做精确化，路由依赖估算**（§4.1 步骤 2）。
- 不可索引的谓词（无对应索引）不进候选集，由 recheck 兜底。

组合候选集就是**交并集结果**——即「把标量索引的交并集结果传给向量查询」这一常见做法。对单谓词场景（`WHERE cat='x'`），单个索引的候选集即精确，无组合问题。

**为什么必须（路由可信性）**：路由依据必须是**覆盖全部可下推谓词**的估算或精确化后的组合计数。单索引超集估算会把高选择率永远挡在精确路径外，**已禁止**（§4.1 步骤 2）；「存在无索引谓词」时连可信估算都凑不齐，走「计数不可信」档（§4.1）。

- **覆盖复合索引优先**：若存在覆盖全部谓词的复合索引，单索引枚举即精确，无需多索引求交（多候选择优已优先选它）。
- **存在无索引谓词**：该谓词无法进入候选集（recheck 兜底），计数不可信 ⇒ 走 §4.1「计数不可信」档（全扫正确基线或显式近似）。
- **精确路径语义**：组合候选集对索引覆盖的谓词精确；recheck 保证最终无假阳性、无漏行。代价是多索引枚举 + 集合运算（候选集规模通常远小于全量，可接受）。
- **OR 并集**：标量 OR（同列 IN/范围）直接支持；跨列 OR 需多索引枚举后求并（实现路线见 §6）。

### 5.2 索引覆盖组合（正确性关键）

标量索引与向量索引**各自只覆盖部分数据文件**（partial index / 未覆盖文件），且覆盖集合可能不同。候选集只在「两索引都覆盖」的文件上成立——**否则受限搜索会漏掉未覆盖文件里满足标量条件的行**。

**实现基础（关键，与代码现状对齐）**：向量索引（IVFPQ）与标量索引（BTree）都是**全局单索引**——一个 segment 一个工件，分区跨多个数据文件，每行记录 `file_index`（向量侧 `file_indices: Vec<u32>` 为代码现状；标量侧**现状**为 `RowAddress{file_path, row_position}` 字符串路径，count 模式**规划**紧凑键 `(file_idx << 32) | row_pos`）。因此「按文件覆盖组合」指**行级过滤策略按文件分组**，而非物理上按文件跑 per-file 子索引。文件级覆盖掩码直接取自现成的 `live_covered_data_files`（向量侧）与标量索引覆盖文件集，两者求交/差集即得各分组。

| 文件覆盖组合 | 行级预过滤 | 搜索内循环的过滤行为 |
|---|---|---|
| 标量 ∩ 向量都覆盖 | 生效 | 逐行查候选位图（(file_index, row_position) 成员判定），命中才算距离入堆 |
| 仅向量覆盖（标量未覆盖） | 不生效 | **不过滤**，候选全部返回 + 事后标量 recheck（该文件退化为现状路径） |
| 仅标量覆盖 / 都未覆盖 | 不生效（向量侧） | 向量索引内无该文件行（不在工件），由全扫兜底 |

- **受限搜索在全局索引内循环逐行过滤**：搜索按最近质心探测分区，分区内逐行算 ADC 距离时——该行 `file_index` 所属文件若在「标量 ∩ 向量覆盖」掩码内 → 先查行级候选位图、命中才算距离；若在「仅向量覆盖」掩码内 → 不过滤（退化为现状，事后 recheck）。其余文件无候选，全扫兜底。保证**无漏行**。
- 计数/路由只统计「标量 ∩ 向量覆盖」文件（预过滤真正生效的范围）；其余文件的成本按现状路径计入路由成本。
- 候选位图按全局 (file_path/file_index, row_position) 组织（与 position deletes 同键空间，复用 RowAddress 判等，file_index 为优化提示不参与判等），**按文件分组存储**（每文件一个行号数组/位图）供内循环 O(1) 判定。
- **精确路径例外**（§4.2 路径一）：候选行在「标量覆盖」文件内枚举，向量按行号取——Phase 1 用数据面 `read_single_file_rows_at`（已存在，按行号读列）；Phase 2 索引直取（fetch_vectors）。「标量未覆盖」文件全扫 + 精确距离并入全局 top-K——精确路径不依赖向量索引覆盖，故「仅标量覆盖」文件也能精确处理。

### 5.3 OR 与 NOT（查询形态边界）

| 形态 | 示例 | 支持 | 处理 |
|---|---|---|---|
| 向量 top-K ∧ 标量 AND | 主场景 | ✅ | 本方案核心路径 |
| 标量 AND 多列 | `WHERE a=1 AND b=2 AND vec~q` | ✅ | 组合候选集（各谓词对应索引求交）+ recheck 兜底 |
| 标量 OR（同列等值） | `cat IN ('a','b')` | ✅（部分） | IN / 范围表达式 → 候选集并集 |
| 标量 OR（跨列/混合算子） | `a=1 OR b>5` | ⚠️ | 需「多集合并集」（实现路线见 §6）；**当前显式回退全扫 + recheck，EXPLAIN 标注「不支持过滤，已回退」** |
| 标量 NOT | `NOT (cat='x')` | ⚠️ | 补集语义对 ANN 无直接帮助；回退全扫 + recheck |
| **向量参与的 OR** | `cat='x' OR vec~q` | ❌ | 结果集非 top-K 形状，ANN 无法直接加速；规划器拆 UNION 或全扫，**列为非目标** |

**原则**：本方案只加速「向量 top-K ∩ 标量 AND」形状。任何不支持的形态**显式回退并告警**（EXPLAIN 标注回退原因），保证正确性（recheck 兜底）优先于性能。

> **向量参与的 OR 的业界处理**：Lance / Milvus / Qdrant / Weaviate 的过滤表达式都是**标量布尔表达式**（AND/OR/NOT 限于标量谓词），向量部分始终是 AND（检索本身），「标量 OR 向量距离」无法在单次过滤 ANN 内表达。业界处理是**两条独立子查询 + 合并**——Lance 的「向量 + 全文两路子查询 + RRF 融合重排」正是这一模式：标量查询 ∪ 向量查询，再按得分合并。本方案同样以「规划器拆 UNION + 合并」为处理方式，列为非目标。

## 6. 实现路线（构建顺序）

> 本文档第 1–5、7 节是**一份完整的目标设计**。本节的 Phase 只是**落地次序**（先正确性、后优化），不是设计变体；每阶段都朝同一目标架构推进，完成后按需求 §八 的**单一验收标准**验收。

### Phase 1 —— 正确性基线（打通全部功能路径）

目标：功能全部可用——高选择率**精确（召回 100%）**、中/低选择率不劣化；性能先保证「不劣化」，优化后置。

**接口新建清单**（代码现状核实，均为从 0 新建而非扩展）：`VectorSearchRequest` 增候选集 + 文件覆盖掩码入参并改写 IVFPQ 内循环；`VectorIndex` 新建 `fetch_vectors`；`ScalarIndex` 新建 count-only 模式；search 内编排自适应 nprobe。下述引擎能力按此清单展开。

**索引引擎**
- 标量**计数查询**（count-only，新建）：每谓词定位键范围累加行数、不物化行地址、可触顶截断、**按 `file_index` 绑定存活文件列表**。
- **组合估算 + 有界精确化**：按谓词逻辑组合各计数（AND 取 min / OR 累加）做路由；多谓词 AND 歧义带枚举最小索引候选行 + 成员判定得精确组合 N；OR 保持估算路由（§4.1 步骤 2）。
- 标量**枚举**：按表达式 + 存活文件返回匹配行集合；**组合候选集**：各索引候选集 AND 求交 / OR（同列 IN）求并 → 精确候选集（执行用，精确/受限路径复用，§5.1）。
- **精确路径**：按行号集合取向量 + 精确距离 + 全局 top-K。Phase 1 用数据面 `read_single_file_rows_at`（已存在，按行号读列）实现；Phase 2 `fetch_vectors` 索引直取高效化。
- 受限路径：向量检索内循环逐行按候选集（位图）+ 文件覆盖掩码过滤（全局单索引，§5.2），全扫兜底同样过滤；`adaptive nprobes` 基础版。
- 混合检索编排：文件级预判 → 每谓词计数 → 组合估算 → 路由（覆盖占比护栏 / 有界精确化 / 现状运行时护栏）→ 枚举/搜索 → 兜底合并。

**桥接**
- 混合检索配置从「向量/标量二选一」扩展为「向量 + 可选标量预过滤」；计数/枚举/搜索编排为一次调用。

**FDW**
- 规划期识别混合查询，匹配标量/向量索引（复用多候选择优），组装混合检索配置。
- EXPLAIN 展示：预过滤索引、路由档、回退原因。
- **回退保护**：不支持的查询形态（跨列 OR / NOT / 向量参与的 OR）在 EXPLAIN 显式告警「将触发全扫，建议改写」；回退路径加运行时成本护栏（行数/时间上限），避免误写查询在并发下打爆 IO。

**验证**：正确性为主——高/中/低三档召回（高选择率在覆盖完整下 = 100%）、无假阳性、路由确定性（组合估算分档 + 有界精确化）、边界场景；**多谓词且存在无索引谓词场景必须验证「计数不可信 → 走正确基线」**；**多谓词有单列索引（无覆盖复合索引）场景必须验证组合估算/有界精确化路由正确**；性能 A/B 记录，性能达标以需求 §八 单一验收为准（构建过程不单独设门槛）。

### Phase 2 —— 优化与扩展

- 精确路径 `fetch_vectors` 高效化（数据面读列 → 索引直取）；自适应 nprobe 策略调优；路由阈值标定（标定脚本，按数据集/硬件产出推荐值）。
- 多谓词扩展：**跨列 OR 并集**（多索引枚举后求并）；无索引谓词的覆盖索引自动建议。
- **覆盖组合处理**（§5.2）：受限搜索按文件覆盖组合分区，Phase 1 先保证正确性、Phase 2 优化成本。
- 成本护栏调优：存活文件数阈值、计数页数上界、回退保护参数（已在 Phase 1 内置）。
- 并发稳定性专项；性能目标收紧（按需求 §八 单一验收）。

### Phase 3（远期）—— 融合索引与统计驱动

- **融合索引**（方案 1 演进）：向量索引构建时可选携带标量属性列，宽过滤内联过滤，服务高基数宽过滤场景。代价：存储放大 + 重建成本。**仅当 Phase 1/2 的宽过滤回退现状成为实测瓶颈后启动**。
- **PQ 码级过滤**（调研报告 P3 方向）：为 PQ 码块附过滤位向量，把过滤判断从逐条推进到逐块。
- **统计驱动 planner**：BTree 层直方图/zone map 做选择性估算，阈值自适应（AnalyticDB 四路径的简化版）。

## 7. 正确性、并发与边界

### 7.1 正确性

| 层 | 机制 | 保证 |
|---|---|---|
| 索引检索 | 候选集过滤 / 精确距离 | 返回行必满足标量条件（无假阳性） |
| 覆盖兜底 | 未覆盖文件全扫并入 | 无漏行（部分覆盖安全） |
| 本地 recheck | FDW 保留原始谓词 | 最终语义正确性最后防线（多谓词/OR 回退均靠此兜底） |
| 内核重排 | 精确距离 + 全局 Top-K | 排序正确 |

**近似语义标注**：受限/现状路径召回受探测簇数与 Fetch-K 控制，属近似；精确路径保证语义。文档与 EXPLAIN 均明确标注。

### 7.2 并发

- **无共享可变状态**：每次查询的候选集（位图/数组）为查询私有，构建与使用均在单查询作用域内；索引 segment 只读共享（沿用现有加载缓存）。
- 标量计数/枚举为只读索引操作，多查询并发安全。
- 自适应 nprobe 只改当前查询的检索参数，不影响其他查询。
- 测试矩阵含并发稳定性场景（长时间运行、随机查询，观察内存与错误率）。

### 7.3 边界与异常

| 场景 | 行为 |
|---|---|
| 标量候选集为空 | 短路返回空结果，不触发向量检索 |
| 无标量索引可匹配 | 回退现状纯向量路径 |
| 标量谓词算子不支持预过滤（如空值判断） | 不进行级预过滤，留文件级裁剪 + recheck |
| 标量/向量索引覆盖不同快照 | 沿用现状覆盖规划，未覆盖全扫兜底 |
| 候选集过大 / 存活文件数超阈值 | 路由现状路径，无退化 |
| 未覆盖文件占比高 | 路由时考虑覆盖比例，占比高则直接现状（避免全扫成为瓶颈） |

## 8. 验收标准

按需求文档 §八 **单一验收标准**（完成态，实现次序见 §6）：

- **功能**：高选择率在**覆盖完整**下精确路径召回 = 100%（覆盖不足按护栏转受限，近似语义，召回 ≥ 现状 post-filter）；中/低选择率无假阳性、不劣化（相对实现前 ±10%）；路由确定性（组合估算分档）；**多谓词且存在无索引谓词 → 计数不可信 → 正确基线**（§4.1/§5.1）；现状档运行时护栏（结果不足时二次精确重路由）；回退形态有 EXPLAIN 告警 + 成本护栏。
- **性能**：按需求 §3.3/§3.4 目标——高选择率相对正确基线（全扫）快 ≥20×、相对近似基线（纯 IVF）≤1.0×（惊喜 ≤0.5×）。
- **并发吞吐**：并发 {1, 8, 32} 下混合查询 QPS 保持率（高 ≥100% 目标 / ≥80% 底线、中 ≥70%、宽 ≈100%），p99 在目标内；三锚点实测后与模型曲线比对。
