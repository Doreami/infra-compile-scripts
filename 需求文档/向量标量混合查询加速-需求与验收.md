## 一、需求概述

### 1.1 背景

「相似度 + 标量约束」是向量检索与关系过滤的交集场景：

```sql
SELECT id FROM tab
WHERE category = 'electronics'
ORDER BY vec <-> '<query_vector>'::vector
LIMIT 10;
```

现状为 post-filter：标量不进向量检索，只做文件级裁剪 + 本地 recheck，靠 FetchK（TopK×5，封顶 10000）兜召回。**高选择率标量下召回无保证（可能静默返回空）**；且全部候选行都要物化。

### 1.2 目标

1. 标量条件从「检索后过滤」前移为「检索内预过滤」，高选择率下**精确**、中等选择率下**近似加速**、低选择率下**不劣化**。
2. 候选行在物化前收窄，命中「物化是最大耗时」的瓶颈。
3. 复用现有标量/向量索引，**不改变索引存储格式**。

### 1.3 非目标

- 向量排序（`ORDER BY vec` 无相似度）加速。
- 融合索引（远期）、规划器成本估算（远期）。
- **多查询向量批量检索**（`IN` 子句 / 子查询）加速——**首期仅支持单向量 Top-K**。
- **向量参与的 OR**（`cat='x' OR vec~q`）——非 top-K 形状，ANN 无法加速，回退保证正确性。
- 不保证近似路径的 100% 召回（近似语义由探测参数控制）。

### 1.4 用户场景

> **验证前提**：本需求的功能/性能验证统一采用**人工可控基数列**（`cat = i % C`）构造选择率；真实业务场景（如 `year>2000`）的选择率特征取决于数据分布，需实测。

| 场景 | 查询形态 | 选择率特征 |
|---|---|---|
| 分类 + 相似度 | `WHERE cat='x' ORDER BY vec<->q LIMIT K` | 视类别基数 |
| 时间范围 + 相似度 | `WHERE ts>'...' ORDER BY vec<->q LIMIT K` | 视窗口大小 |
| 多条件 + 相似度 | `WHERE user_id=N AND status='x' ORDER BY vec<->q LIMIT K` | 通常很高 |
| 宽过滤 + 相似度 | `WHERE year>2000 ORDER BY vec<->q LIMIT K` | 视数据分布（可能高也可能低） |

## 二、功能需求

| # | 能力 | 说明 |
|---|---|---|
| F1 | 混合查询识别 | 规划期识别「向量 top-K + 可下推标量谓词」并存 |
| F2 | 索引匹配 | 匹配标量/向量索引；多谓词为每个可下推谓词匹配对应标量索引 → **组合候选集**（求交/求并） |
| F3 | 标量预过滤 | 标量表达式进向量检索内做行级过滤（计数 → 候选集） |
| F4 | 三级路由 | 按存活文件内候选行数自动选：精确 / 受限 / 现状 |
| F5 | 高选择率精确 | 候选集小时返回「标量匹配行内真正最近 K 行」 |
| F6 | 兜底正确 | 本地 recheck + 未覆盖文件全扫，无漏行无假阳性 |
| F7 | 不劣化 | 低选择率回退现状，行为与实现前等价 |
| F8 | 可观测性 | EXPLAIN 展示预过滤索引、路由档、回退原因 |

## 三、主成功场景设计

### 3.1 场景定义

**数据**：复用现有 SIFT（100万/128维）与 GIST（100万/960维）表（`bucket[32]` 分区，官方 query 文件）。在表上**新增合成标量列**（`cat = i % C`），用基数 C 控制选择率：

| 档 | 选择率 | SIFT 匹配行数 | 期望路由 |
|---|---|---|---|
| 高 | 1% | ~1 万 | 精确 |
| 中 | 5% | ~5 万 | 受限 |
| 中-宽 | 50% | ~50 万 | 受限/现状 |
| 宽 | 99% | ~99 万 | 现状（回退） |

**查询**：`SELECT id FROM <t> WHERE cat = <c> ORDER BY vec <-> '<q>'::vector LIMIT K`，K ∈ {10, 100}，DOP ∈ {1, 8}。

**正确性基准（GT）**：对每个查询向量，暴力扫描「标量匹配行」做精确距离取 Top-K（改造 gen_groundtruth.py：加 mask 入参 + 对匹配子集暴力算，见 §4.1）。该 GT 是「过滤后精确基准」，报告中标注生成方式。

### 3.2 指标定义

| 指标 | 定义 | 口径 |
|---|---|---|
| 延迟 | 单查询 p50 / p99 | `EXPLAIN ANALYZE` 的 Total runtime（含桥接 I/O） |
| 吞吐 | 并发下 QPS | 多连接并发，测稳定吞吐 |
| 召回 | Recall@K | 相对「标量匹配行内精确 Top-K」GT |
| 假阳性 | 返回行不满足标量条件的比例 | 应为 0 |
| 劣化 | 混合查询 vs 实现前同查询的延迟比 | 分档评估 |

### 3.3 目标值（首版，实现后以同环境 A/B 实测校准）

> 推导基准：纯向量检索实测（IVF K=10，DOP=1/DOP=8）：SIFT 212/63ms、GIST 1467/311ms；标量点查 SIFT/GIST 24–29ms。目标值标注「待校准」。

**对比口径（关键，必须先对齐正确性）**：

- **近似基线**：纯 IVF post-filter（现状实际行为）——结果**不保证正确**（高/中选择率下召回无保证）。
- **正确基线**：全扫 + recheck（现状要拿到**正确**混合结果只能全扫）：SIFT K=10 = 2358ms、GIST = 18883ms。
- 混合查询的目标是「**正确结果**」。因此性能对比分两层：
  - 相对**正确基线（全扫）**：**必赢项**（硬价值，验收门槛）；
  - 相对**近似基线（纯 IVF）**：**目标项**（含标量预过滤固定开销后的目标），并有「惊喜项」。

**说明**：
- 下述目标（必赢/目标/惊喜、并发保持率）即**最终验收标准**，按完成态验收；实现可先落正确性、后优化性能（见设计 §6 实现路线），**中间构建形态不单独设验收档**。
- **多谓词且无覆盖复合索引**时，路由按「计数不可信」走正确基线（全扫），保证召回 100%，性能为已知代价（见设计 §4.1/§5.1）。
- **路由阈值按数据集维度分档**：SIFT 精确 10K / 忽略 100K，GIST 精确 2K / 忽略 20K（保守默认值，见设计 §4.1），实现后以标定脚本校准。

**SIFT（主场景，K=10）**

| 档 | 选择率 | 召回目标 | 相对正确基线（全扫 2358ms） | 相对近似基线（纯 IVF 212ms） |
|---|---|---|---|---|
| 高 | 1% | **100%**（精确） | **快 ≥20×（必赢）** | **≤1.0×（目标）；≤0.5×（惊喜）** |
| 中 | 5% | ≥ IVF post-filter 召回（90.6%@10） | **快 ≥5×（必赢）** | 方向 ≤1.0×，保底 ≤1.5× |
| 中-宽 | 50% | ≥ IVF post-filter 召回 | 快 ≥3×（必赢） | 方向 ≤1.0×，保底 ≤1.5× |
| 宽 | 99% | = 纯 IVF 召回 | 快 ≥10×（纯 IVF 本身，必赢） | ±10%（不劣化） |

**GIST（主场景，K=10）**

| 档 | 选择率 | 召回目标 | 相对正确基线（全扫 18883ms） | 相对近似基线（纯 IVF 1467ms） |
|---|---|---|---|---|
| 高 | 1% | **100%** | **快 ≥20×（必赢）** | ≤1.0×（目标）；≤0.5×（惊喜） |
| 中 | 5% | ≥ IVF post-filter 召回（78.4%@10） | **快 ≥5×（必赢）** | 方向 ≤1.0×，保底 ≤1.5× |
| 中-宽 | 50% | ≥ IVF post-filter 召回 | 快 ≥3×（必赢） | 方向 ≤1.0×，保底 ≤1.5× |
| 宽 | 99% | = 纯 IVF 召回 | 快 ≥12×（必赢） | ±10%（不劣化） |

> **指标分级说明**：
> - **必赢**（硬验收门槛）：相对全扫快 ≥20×——高选择率精确路径几乎必然成立（精确 ≈ 100–300ms vs 全扫 2358ms），是能力质变点。
> - **目标**（期望达成）：相对纯 IVF ≤1.0×——「不慢于近似基线」且召回 100% 是质变。**与实现阶段的绑定**：精确路径 Phase 1 用数据面顺序读列（`read_single_file_rows_at`）实现，相对纯 IVF 目标暂放宽至 ≤1.5×（以正确性为先）；Phase 2 `fetch_vectors` 高效化（索引直取）后收紧至 ≤1.0×。
> - **惊喜**（不强制）：≤0.5×，物化收窄的直接收益，实测达到即超额。
> - **召回基线的含义**：近似路径的召回底线是「纯 IVF post-filter 召回率」（SIFT 90.6%、GIST 78.4%），**不是** 100%；精确路径必须 100%。

### 3.4 并发与吞吐目标（并发曲线）

> **模型**（推导值，待同环境多连接实测校准）：单连接 QPS₀ = 1000 / 延迟；每查询 CPU 时间 ≈ 延迟 × DOP；理论吞吐上限 = 核数 / CPU 时间；目标吞吐取上限 50%（工程裕量：I/O、桥接、调度、内存带宽）。机器 96 核。**三个实测锚点（单连接 / 并发 8 / 饱和点）填充后线性插值。**

**基线并发曲线（纯向量检索 K=10，96 核）**

| 数据集 | DOP | 单连接 QPS₀（实测延迟） | 每查询 CPU | 理论上限 | 目标吞吐（50%） | 饱和并发（核数/DOP） |
|---|---|---|---|---|---|---|
| SIFT | 1 | 4.7（212ms） | 212 core-ms | ≈453 | ≈226 | ≈96 |
| SIFT | 8 | 15.9（63ms） | ≈504 core-ms | ≈190 | ≈95 | ≈12 |
| GIST | 1 | 0.7（1467ms） | 1467 core-ms | ≈65 | ≈33 | ≈96 |
| GIST | 8 | 3.2（311ms） | ≈2488 core-ms | ≈39 | ≈19 | ≈12 |

> DOP=1 的理论上限（453）假定零竞争，仅作上限参照，验收以实测为准。

**SIFT DOP=8 并发曲线（主场景参考形态）**

| 并发 n | 目标 QPS | 目标 p99 | 说明 |
|---|---|---|---|
| 1 | ≈16（实测锚点） | <100ms | 单连接 |
| 4 | ≈64 | <200ms | 近线性区 |
| 6 | ≈95 | <250ms | 达目标吞吐（50% 上限） |
| 8 | ≈105 | <350ms | 增速趋缓 |
| 12 | ≈115 | <500ms | 饱和点（核数/DOP≈12） |
| 32 | 持平或略降 | <800ms | 超饱和，p99 劣化，QPS 不增 |

**混合查询目标曲线（SIFT 主场景；全扫 QPS≈0.4 为 SIFT 值）**

| 档 | 单连接延迟（vs 纯 IVF） | 并发 QPS 保持率（vs 纯 IVF） | 相对正确基线（全扫） |
|---|---|---|---|
| 高选择率（精确） | ≤1.0×（目标）；≤0.5×（惊喜） | **≥100%（目标）；≥80%（底线）** | 高 10–100× |
| 中等（受限） | 方向 ≤1.0×，保底 ≤1.5× | ≥70%（底线） | 高 5×+ |
| 宽（回退） | ±10% | ≈100% | 高 ~10×（纯 IVF 本身） |

> **保持率口径**：相同并发下，混合查询 QPS 相对纯 IVF 的保持率。高选择率「≥100% 为目标、≥80% 为不合格即失败的底线」——精确路径延迟 ≤1.0×（单连接 QPS ≥ 纯 IVF），并发下理应不劣于纯 IVF；若实测 ≤0.5× 延迟，保持率应显著高于 100%。中等 ≥70% 允许固定开销带来的并发损耗。真正价值在相对正确基线：混合查询 QPS 是全扫的 10–100 倍。

## 四、测试方案

整个测试最好能一键执行，方便看护。

### 4.1 测试数据准备

1. 现有 SIFT / GIST 表（已导入、已建 IVFPQ 索引，1024 簇）。
2. 新增合成标量列 `cat`（基数 C 控制选择率：100/20/2/1）与 `tag`（多谓词场景用）：**改造 `setup_fixed.py` 的表 append 逻辑**（现只写 [ids, vec]，需追加 cat/tag 列），作独立数据准备子任务。
3. 标量侧建 BTree 索引（单列；按专项场景决定是否建 (cat)、(tag) 或 (cat,tag) 复合索引）。
4. 混合 GT 生成：**改造 `gen_groundtruth.py`**（纯暴力 KNN，直接读 .fbin/.fvecs 算全局 Top-K，无标量概念）——新增 mask 入参（按 `cat = id % C` 由行号推出匹配子集）+ 对匹配子集暴力算精确 Top-K + 缓存键含标量条件；K=100，多谓词组合复用缓存。

### 4.2 测试方法

- **冷启动**：重启实例 + 清 OS 缓存 + 单次执行（避免预热掩盖差异）。
- **热查询**：预热后计时（多轮平均）。
- **并发**：1 / 8 / 32 连接，测稳定吞吐与 p99。
- **A/B 同环境**：实现前后在**同一环境、同一数据、同一查询集**下对比。
- 环境固定：CPU/内存/存储/索引参数（nprobe 等）/DOP 均记录在报告。
- **GT 缓存**：GT 结果按「查询向量 + 标量条件组合」落盘缓存，避免重复计算；不同 K（10/100）复用同一 GT（Top-100 含 Top-10）。

### 4.3 测试矩阵（轻量 / 全量两档）

```
数据集 {SIFT, GIST} × 选择率 {1%, 5%, 50%, 99%} × K {10, 100} × DOP {1, 8} × 并发 {1, 8, 32}
指标：p50 / p99 延迟、QPS、recall@K、假阳性
对比：实现前（post-filter） vs 实现后
并发曲线锚点：单连接（QPS₀）、并发 8、饱和点（≈核数/DOP）
```

- **轻量验证模式**（日常 CI / 快速看护）：取前 100 个查询向量采样 + 仅 SIFT + DOP=8 + 并发 8 + 全部选择率；GT 用缓存。
- **全量验收模式**（上线前/定期）：跑满上述矩阵 + 冷启动 + 火焰图；可放周末定时任务。
- GT 生成本身（全扫带标量 mask）耗时大：SIFT 全扫 2358ms × 100 查询 ≈ 4 分钟/档，GIST 18883ms × 100 ≈ 30 分钟/档；**采样 100 个查询向量 + 缓存**，四档选择率合计可控制在数小时内。

**专项场景（多谓词与覆盖护栏，单独执行）**
- **多谓词有单列索引（无覆盖复合索引）**：`WHERE cat=1 AND tag=2`，仅建单列索引 (cat)、(tag) → 组合估算/有界精确化路由，验证路由分档正确、无漏行、无假阳性。
- **多谓词存在无索引谓词**：`WHERE cat=1 AND tag=2`，仅建 (cat) → 「计数不可信」→ 正确基线（全扫），召回 100%、EXPLAIN 标注、性能为已知代价（见 §3.3）。
- **标量∩向量覆盖占比边界**：构造「仅标量覆盖（向量未覆盖）」文件占存活文件比例落在护栏阈值两侧（如 5% / 15%），验证：护栏触发时转受限且无漏行、未触发时精确路径正常、延迟在预算内（见设计 §4.1 精确路径成本护栏）。

### 4.4 回归与边界

- 纯向量查询（无标量）不回归：延迟/召回与实现前一致。
- 纯标量查询（无向量）不回归。
- 路由确定性：谓词顺序 / 建索引顺序 / 多候选并存（与多候选择优叠加）。
- 边界：候选集为空（返回空）、候选集恰为 K、单文件 vs 多文件、**索引覆盖组合**（标量/向量部分覆盖的四种组合，验证无漏行）、**存活文件数超阈值**、**计数触顶 / 组合估算与有界精确化分档边界**、**覆盖占比护栏阈值两侧**。
- **并发稳定性**：长时间随机查询，观察内存与错误率。

### 4.5 一键执行

整个测试（数据准备 → 建索引 → 跑矩阵 → 出报告）封装为**单一入口脚本**，区分**轻量 / 全量**两档，输出结构化结果（JSON + 摘要表），便于日常看护与归档复现。

## 五、与融合索引的性能优劣场景

融合索引（方案 1：向量索引存储中携带标量列）为远期演进。两者性能差异分场景验证：

| 场景 | 方案 3（双索引 + 预过滤） | 融合索引（方案 1） | 结论 |
|---|---|---|---|
| **高选择率（1%）** | 精确路径，召回 100%，无冗余存储 | 内联过滤为近似；探测簇内匹配稀疏时可能漏 | **方案 3 完胜**（精确 + 零存储放大） |
| **中等（5%）** | 受限检索 + 标量搜索先行（+24–29ms 固定开销） | 内联过滤，单索引一次加载 | 延迟接近；方案 1 略优（无两阶段） |
| **宽过滤（99%）** | 回退现状 post-filter | 内联过滤跳过非匹配向量，≈ 纯 IVF 延迟 | **方案 1 占优**（宽过滤高基数场景） |
| 构建/存储 | 无冗余、无重建 | 存储放大、标量列固化、重建成本 | **方案 3 占优** |

**决策**：先落地方案 3（覆盖高选择率痛点 + 零格式改动）。**仅当「宽过滤高基数」成为业务主峰且实测成为瓶颈时，启动融合索引**——两者互补，不冲突。

## 六、劣化场景分析（相对实现前）

实现后须**验证并控制**以下潜在劣化，逐项有对策：

| # | 劣化场景 | 根因 | 对策与验收 |
|---|---|---|---|
| 1 | **高文件数 + 行级预过滤变慢** | 标量预过滤阶段继承 btree 的随文件数元数据解析开销（实测 DEEP 1024 文件：btree 976ms vs 全扫 261ms） | 存活文件数 > 阈值（如 512）直接回退现状，跳过行级 |
| 2 | **宽过滤识别本身浪费** | 判「大→回退」需先跑标量计数 | 文件级预判（存活占比 > 90% 直接回退）；每谓词 count-only 计数 + 组合估算，可触顶截断；多谓词宽不枚举（现状档运行时护栏兜底） |
| 3 | **精确路径误判变慢** | 精确阈值设错（候选集实际很大）→ 精确扫描比 ANN 慢 | 阈值保守 + 精确路径内部按行数再路由（超限立即切受限） |
| 4 | **中等选择率召回回归** | 受限路径探测簇数不足 → 召回低于现状 post-filter | 自适应放大探测簇数（§4.3）；验收 recall ≥ 纯 IVF 召回 |
| 5 | **候选集内存/判断开销** | 中等选择率候选集（5%×10M≈50 万行）集合表示 | 紧凑表示（每文件位图）；大数据量专项 |
| 6 | **计划期开销** | 规划期多匹配一个索引 + 组装配置 | match_index 一次返回全量；验证规划时间增幅可忽略 |
| 7 | **并发吞吐受精确路径 CPU 占用影响** | 精确路径全量距离为 CPU 密集 | 验收按「保持率」定义（§3.4） |
| 8 | **空结果探测延迟** | 高文件数下确定候选集为空需跨文件元数据解析 | 验收：**空结果探测延迟 ≤ 纯向量检索延迟的 10%** |
| 9 | **回退查询（非目标形态）无保护** | 误写跨列 OR / NOT / 向量参与的 OR 触发全扫（GIST 18.9s），并发下打爆 IO | FDW 层 EXPLAIN 告警「将触发全扫，建议改写」+ 回退路径行数/时间成本护栏 |
| 10 | **高选择率查询因覆盖不足被降级受限** | 标量∩向量覆盖不完整，「仅标量覆盖」文件占比超护栏 → 高选择率查询转受限（近似语义），不再保证精确召回 100% | 覆盖占比护栏成本化（预算 = 纯 IVF × 精确预算系数；容忍占比按**数据量占比**口径 = 预算 / 全扫总延迟，SIFT≈9% / GIST≈8%，**基于 32 文件均匀基准，实际以标定脚本校准**，口径定义见设计 §4.1）；受限下「仅标量覆盖」文件仍全扫精确并入（无漏行）；EXPLAIN 标注路由档与原因；验收：召回 ≥ 现状 post-filter、延迟 ≤ 受限预算 |

**总原则**：任何近似路径的召回不得低于实现前；任何场景的延迟劣化不得超过阈值（见 §3.3 宽档 ±10%）；正确性（无假阳性、无漏行）始终不变。

## 七、官方 benchmark 调研

**结论：业界事实标准是 VectorDBBench（开源、厂商中立），含官方「过滤检索」场景；无针对「数据湖 + gaussdb」的官方混合查询 benchmark，需自建（采用 VectorDBBench 场景结构）。**

| 来源 | 类型 | 过滤/混合场景 | 可用性 |
|---|---|---|---|
| **VectorDBBench**（Zilliz，MIT 开源） | 开源事实标准 | **官方 Filtering Search 场景**：1M/10M × 768 维 × {低过滤率 1%, 高过滤率 99%}，报告构建/召回/延迟/最大 QPS，含并发；2026-08 起加成本维度（Payload-aware search） | 方法论可直接采用；可跑同一用例对比外部系统 |
| VectorDBBench 2026-03 榜单（Lindorm） | 上榜数据 | 向量主导（宽过滤）5 万+ QPS；标量主导（高选择率，位图/倒排）26 万+ QPS，PR #718 可复现 | 外部校准锚点 |
| VecBench（2025，arXiv 2509.07789） | 学术 | 系统评估过滤 ANN 的选择率影响 | 方法论参考 |
| big-ANN / Filtered-DiskANN | 学术/挑战赛 | 带过滤轨迹的大规模 ANN | 方法参考 |

**本项目方案**：采纳 VectorDBBench 的过滤场景结构（1%/99% 过滤率、并发、QPS/召回/延迟三指标），套用本项目的 SIFT/GIST 数据与现有测试工具链，GT 用「标量匹配行内暴力精确 Top-K」，形成自有混合 benchmark（§四）。

## 八、验收标准（勾选清单）

以下为**完成态验收**（性能目标见 §3.3/§3.4）。实现可先落正确性、后优化性能（见设计 §6 实现路线），**中间构建形态不单独设验收档**。

> **构建期检查点（非验收档）**：Phase 1 完成时以功能正确性为准（高选择率精确召回 100%【覆盖完整】、无假阳性、无漏行、路由确定性）+ 无显著性能劣化（高选择率相对全扫仍快 ≥3×），即可进入 Phase 2 优化。该检查点只用于推进实现次序，不替代下述完成态验收。

**功能**
- [ ] 混合查询被识别并走「向量 + 标量预过滤」路径（EXPLAIN 可见）
- [ ] 高选择率（1%）在**覆盖完整**下路由精确路径，召回 = 100%；覆盖不足时按覆盖占比护栏转受限（近似语义，召回 ≥ 现状 post-filter）
- [ ] 中/宽选择率路由受限/现状路径，行为与设计一致
- [ ] 标量候选集为空返回空结果，不触发向量检索
- [ ] 返回行无假阳性（全部满足标量条件）
- [ ] 不支持的查询形态（跨列 OR、向量参与的 OR）显式回退并 EXPLAIN 标注，正确性由 recheck 保证；回退路径有成本护栏
- [ ] **多谓词且存在无索引谓词** → 走「计数不可信」正确基线，召回 100%（设计 §4.1/§5.1）
- [ ] **多谓词有单列索引（无覆盖复合索引）** → 组合估算/有界精确化路由正确，无漏行无假阳性
- [ ] **现状档运行时护栏**：估算误判高选择率为宽时，post-filter 结果不足 K 触发二次精确重路由

**性能（同环境 A/B，SIFT/GIST）**
- [ ] 高选择率：相对全扫快 ≥20×（必赢）、相对纯 IVF ≤1.0×（目标）、召回 100%
- [ ] 中等选择率：相对全扫快 ≥5×（必赢）、相对纯 IVF 保底 ≤1.5×、召回 ≥ 纯 IVF 召回
- [ ] 宽过滤：延迟与实现前 ±10% 内，无劣化
- [ ] 纯向量 / 纯标量查询不回归
- [ ] 并发曲线：并发 {1, 8, 32} 下 QPS 保持率（高 ≥100% 目标 / ≥80% 底线、中 ≥70%、宽 ≈100%），p99 在 §3.4 目标内
- [ ] 空结果探测延迟 ≤ 纯向量检索延迟的 10%

**稳定性**
- [ ] 路由确定性（谓词/建序/多候选并存）
- [ ] 索引覆盖组合（标量/向量部分覆盖）无漏行；候选集边界、存活文件数超阈值、计数触顶场景正确
- [ ] 高文件数、大数据量候选集场景专项通过
- [ ] 并发稳定性（长时间随机查询，无内存/错误异常）
